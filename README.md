# @trof_r/skills-installer

CLI для установки, обновления и удаления скиллов AI-агентов **в проекте или глобально**.
Поддерживает Claude Code, Codex, OpenCode, Pi и Cursor. Источники: локальная папка,
архив `.tar.gz`/`.tgz` или собственный registry. Интерфейс на русском.
Npm-пакет — `@trof_r/skills-installer`, команда запуска — `skills-installer`.

Требования: macOS или Linux, Node.js **≥22.20.0**, npm. Windows x64/NTFS проходит
заключительную приёмку; проверенные среды и ограничения — в [матрице проверок](docs/windows-validation.md).
Для разработки зафиксирован npm 11.19.0.
Функциональная часть реализована; итоговая проверка релиза ещё не завершена.

## Запуск

Из репозитория:

```sh
npm ci
npm run dev -- --help
npm run dev -- add ./demo
```

Всегда передавайте аргументы после `--`: `npm run dev -- list --global`.
Без разделителя npm может забрать флаги себе.

Для работы в другом проекте соберите CLI и используйте абсолютный путь:

```sh
npm run build
alias skills-installer='node /absolute/path/to/ai-tools-cli/dist/cli.mjs'
cd /path/to/your-project
skills-installer --help
```

Замените пути своими. Далее примеры используют этот alias; установленный из npm-архива
bin называется так же. Команда установки скилла — `add`.

Адаптация Windows ещё проходит приёмку. Для npm-пакета предусмотрен
`skills-installer.cmd`: в PowerShell используйте его явно, если политика выполнения
блокирует npm-файл `skills-installer.ps1`. Аналогично из репозитория доступен
`npm.cmd run dev -- --help`. Менять ExecutionPolicy или запускать терминал от
администратора для CLI не требуется. Нативная проверка PowerShell/cmd остаётся
частью итоговой Windows-матрицы.

В npm 11.19 Windows `.cmd` shim не поддерживает метасимволы cmd в собственном пути
([npm/cmd-shim#45](https://github.com/npm/cmd-shim/issues/45)). Для локальной npm-установки
и глобального prefix используйте пути без `&`, скобок, `%`, `!` и `^`.
Рабочий каталог CLI и путь источника проверяются отдельно и могут содержать эти символы.

## Основные команды

```sh
skills-installer add ./my-skill              # папка с SKILL.md
skills-installer add ./my-skill.tgz          # локальный архив
skills-installer add api-contract-check     # актуальная версия из registry
skills-installer find api-                  # поиск по префиксу slug
skills-installer list                       # установки текущего проекта
skills-installer update                     # обновить все подходящие скиллы
skills-installer remove                     # выбрать скиллы для удаления
```

`add` и выбранный результат `find` проходят шаги: **область → агенты → карточка → подтверждение**.
В обеих областях Codex, OpenCode, Cursor и Pi закреплены в блоке «Всегда включены».
Claude Code добавляется вручную: поиск по названию или ID без учёта регистра,
стрелки перемещают курсор, пробел переключает отметку, Enter подтверждает.
Backspace удаляет символ запроса; отметки сохраняются при фильтрации. Esc/Ctrl+C
отменяют меню. Явный `-a` задаёт точный список без закреплённой группы и без меню.
Блоки меню отделены линиями. В меню и поиске активный пункт белый, остальные
варианты серые; цветом выделяется только значок выбора.
Итоговое подтверждение по умолчанию — «Нет».
В карточке агенты с одинаковым путём установки показаны одной строкой.

В find длинные результаты сокращаются многоточием; полные данные есть в карточке.
Запрос, результаты и подсказки клавиш отделены линиями; в маленьком окне подсказки компактные.
При слишком маленьком окне увеличьте терминал для продолжения выбора.
Esc/Ctrl+C останавливают локальную подготовку до подтверждения установки.

| Параметр           | Назначение                                                                   |
| ------------------ | ---------------------------------------------------------------------------- |
| `-g`, `--global`   | Глобальная область; без него list/update/remove работают с текущим каталогом |
| `-a`, `--agent`    | Явный агент; повторяйте для нескольких, например `-a codex -a pi`            |
| `-y`, `--yes`      | Пропустить итоговое подтверждение add/find/update/remove                     |
| `--force`          | В add/update/find разрешить замену ручных правок управляемого скилла         |
| `--registry <url>` | Registry для add/find                                                        |
| `--without-stat`   | Отключить статистику registry для команды                                    |

Идентификаторы агентов: `claude-code`, `codex`, `opencode`, `pi`, `cursor`.
Для list/update/remove отсутствие `-a` означает все зарегистрированные подключения.
`update -a` выбирает скиллы, но обновление общей копии затрагивает **всех** их агентов.

Без TTY установка требует `-a` и `--yes`; удаление — явные имена и `--yes`,
обновление с изменениями — `--yes`. В TTY `--yes` сохраняет меню области/агентов и выбор скиллов.

```sh
skills-installer add ./my-skill -g -a codex -a pi --yes
skills-installer list -g
skills-installer update demo -g --yes
skills-installer remove demo other -g -a pi --yes
```

## Registry и версии

URL: `--registry` → `SKILLS_API_URL` → `http://localhost:8000`.
Нужен работающий backend с опубликованными скиллами; авторизация не поддерживается.
Существующий локальный путь имеет приоритет перед slug; `./demo` явно обозначает папку.

```sh
export SKILLS_API_URL=https://registry.example.test
skills-installer add demo
skills-installer add demo@1.2.3 -a codex    # закрепить версию или откатиться
skills-installer add demo -a codex          # снять фиксацию, перейти на latest
skills-installer update demo --yes
```

`latest` выбирает текущую версию registry при запуске update. `exact` закрепляет полную SemVer-версию:
update пропускает её даже с `--force`. Локальные источники обновляются из сохранённой
папки/архива. Update использует registry из lock, независимо от нового `SKILLS_API_URL`.

List показывает имя скилла, установленную версию и агентов. Карточка установки
показывает выбранную версию, краткое описание, источник и пути установки. List не обращается к registry
для проверки актуальности и не запускает обновление.

Долгие операции в терминале показывают индикатор с подписью этапа после 200 мс
ожидания. Перед вопросами и выводом результата он очищается; без TTY анимации нет.

`find` ищет по буквальному префиксу slug от двух символов, с учётом регистра.
В TTY позволяет выбрать и установить с политикой latest; без TTY только выводит таблицу.

## Файлы и безопасная работа

| Область   | Общая копия                | Состояние установок                             |
| --------- | -------------------------- | ----------------------------------------------- |
| Проект    | `.agents/skills/<name>/`   | `skills-installer-lock.json` в текущем каталоге |
| Глобально | `~/.agents/skills/<name>/` | `~/.agents/skills-installer-lock.json`          |

Локальная область — текущий каталог, без поиска Git-root; установка в самом home запрещена.
Новые подключения Codex/OpenCode/Cursor/Pi читают общую копию в обеих областях;
Claude Code получает отдельную обычную копию в `.claude/skills` в проекте,
а глобально — ссылку с учётом `CLAUDE_CONFIG_DIR`.
Выбор агентов управляет подключениями, но не изолирует видимость общего каталога.
Все пути и env-переопределения — в [описании Installer](docs/installer.md).

Повторный add сохраняет прежние подключения. Обе проектные копии имеют одну версию
и один эталонный хеш; обновление проверяет и меняет все зарегистрированные копии.
Ручные правки любой копии защищены от замены без
`--force`; чужие каталоги не перезаписываются. Смена источника того же имени требует remove/add.
**Remove последнего подключения удаляет общую копию, включая ручные правки**, сохраняя исходник.

Коммитьте общий каталог, проектную копию Claude и `skills-installer-lock.json` вместе.
До первого `git add` задайте attributes обоих деревьев и убедитесь, что ignore-правила
не скрывают вложенные ресурсы: [перенос через Git](docs/state.md#перенос-проекта-через-git).
После clone подключения уже доступны агентам; отдельной команды repair/setup нет.
Добавьте в `.gitignore` служебные `.agents/.skills-installer-work-*/`,
`.skills-installer-operation.lock`, `.skills-installer-lock-*.tmp`.
`skills-lock.json` другого установщика CLI не читает и не изменяет.

Registry-операции отправляют события download/install. Отключение: `--without-stat`,
`DISABLE_TELEMETRY=1` или `DO_NOT_TRACK=1`. Ошибка доставки не меняет результат команды.
Код завершения: 0 — успех, отсутствие изменений или отмена; 1 — ошибка, включая частичный результат.

## Разработка и документация

```sh
npm run type-check
npm run lint
npm run format:check
npm run test:run
npm run build
npm run package:check
```

Тесты используют временные cwd/home и подменяемый HTTP; сетевым интеграционным тестам
нужен доступ к localhost. `npm run test` — watch, `npm run format` — форматирование.
Git roundtrip входит в `test:run`: настоящий commit/clone на текущей ОС,
NFC/NFD и `core.autocrlf=false/true`, сохранность bytes/hash и работа CLI после clone.
Для отдельного прогона без предварительной сборки: `npm run test:git`.

CI содержит семь jobs: Ubuntu/Node 24 выполняет статические проверки, build,
publint и обычный `npm pack`; шесть комбинаций Linux/macOS/Windows × Node 22.20/24
выполняют build, Vitest и установку одного общего Linux-архива.
Готовый архив из CI можно проверить локально:

```sh
npm run package:smoke -- /absolute/path/package.tgz
```

Smoke проверяет состав, версию, shebang и executable-mode в tar, затем устанавливает
архив локально и в отдельный глобальный prefix с `--omit=dev`. Настоящие bin
(Windows `.cmd`) выполняют `--help` и `--version`. Дочерним процессам передаётся
системный allowlist; home/tmp/npmrc/cache, Windows-профили, XDG и каталоги агентов
изолированы. `NODE_OPTIONS` и пользовательская npm-конфигурация не наследуются.
Архив не перепаковывается. Полный add/update/remove и сложные cwd/source проверяются
в Vitest; перенос Git между разными ОС и создание npm-архива на Windows/macOS
в CI не проверяются. Нативная приёмка Windows обычным пользователем остаётся
отдельной проверкой.
`npm run changeset` создаёт заметку об изменениях. Публикация запускается вручную
через отдельный GitHub Actions workflow и использует тот же проверенный архив.
