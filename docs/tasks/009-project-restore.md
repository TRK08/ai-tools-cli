# 009. Проектный restore

## Цель и входные условия

После аппрува 008 восстановить проектные копии и общие подключения строго по lock. Команды: `restore` и `restore --force`. Требования — [SPEC.md](SPEC.md); для понимания старого сценария посмотреть `../../../skills/src/install.ts`, но его формат состояния и вызовы команд не переносить.

## Работы

1. Зарегистрировать restore в Commander. Работать только с cwd проекта; `-g`, `-a` и позиционные имена для этой MVP-команды не поддерживать. Меню выбора агентов отсутствует.
2. Прочитать и проверить весь lock до изменений. Отсутствующий/повреждённый файл — ошибка, корректный пустой lock — нет изменений.
3. Для каждой записи проверить общую копию. Если её contentHash совпадает, использовать её без скачивания/чтения исходника и восстановить недостающие подключения.
4. Если копия отсутствует, получить источник из lock. Для registry запросить фактически записанную версию независимо от latest; проверить digest архива и contentHash.
5. Для локальной папки/архива требовать доступный источник и тот же contentHash после подготовки. Изменение или недоступность необходимого источника — ошибка по скиллу; не принимать новое содержимое и не обновлять эталон.
6. Существующая отличающаяся копия, в том числе с частично удалёнными файлами, защищена от замены без force. Force не позволяет восстановить источник с другим хешем или занять чужое назначение.
7. Восстановить список агентов из lock через общее ядро. Сохранить записанные версию, политику и желаемые подключения; ошибки не удаляют их из общей конфигурации.
8. Если ни одно запрошенное подключение не удалось, применить правило сохранения прежней копии/состояния. Если возник частичный результат — сообщить о нём, продолжить остальные записи, вернуть итоговый код 1.
9. Повторный restore без изменений — без лишних скачиваний, замен и изменений lock.
10. Описать в README, что restore возвращает оригинал по lock, а пользовательские закоммиченные правки возвращаются через Git. Добавить Changeset.

## Критерии готовности

- [ ] После переноса проекта восстанавливаются относительные подключения и отсутствующие копии.
- [ ] Registry latest в lock не приводит к обновлению при restore: берётся записанная версия.
- [ ] Изменённый локальный источник отвергается даже с force.
- [ ] Целая правильная копия позволяет восстановить ссылки без доступного исходника/сети.
- [ ] Защищённая изменённая копия заменяется только с force и только правильным источником.
- [ ] Сбой не удаляет желаемую конфигурацию, остальные скиллы продолжают обрабатываться.
- [ ] Глобальный restore и интерактивный выбор агентов отсутствуют.

## Проверки

- Общие проверки из индекса; полный перенос проекта между временными корнями.
- Нет общей копии, нет одной/нескольких ссылок, всё на месте, корректный пустой lock.
- Нет/повреждён lock: отсутствие файловых изменений.
- Источник отсутствует или изменён, но установленная копия правильная: восстановление только ссылок без получения источника.
- Источник необходим и недоступен/изменён: ошибка; другая запись успешно восстанавливается.
- Registry выпустил новую версию после записи lock: восстановлена старая, latest сохранён как политика будущего update.
- Отличающаяся установленная папка и частично удалённые файлы с/без force.
- Force с неправильным хешем источника или чужой папкой назначения не проходит.
- Повторный restore: нулевые лишние скачивания и неизменный lock.
