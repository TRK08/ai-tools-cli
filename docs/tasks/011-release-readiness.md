# 011. Итоговые проверки, CI и упаковка

## Цель и входные условия

После аппрувов 010, 012 и 013 подтвердить готовность MVP как установленного npm-пакета вне репозитория разработки. Порядок 010 → 012 → 013 → 011 согласован пользователем 2026-10-13. Требования — [SPEC.md](SPEC.md), стек/релизные инструменты — [000-stack.md](000-stack.md).

Публикация не входит в задачу. Финальный аппрув MVP не запускает npm publish, changeset publish, push или создание релиза автоматически.

## Работы

1. Прогнать полную регрессию команд и интеграционную матрицу ниже. Проверить сборку и установку на macOS/Linux с базовым Node 22.20 и поддерживаемой веткой Node 24 (для сборки не ниже 24.11).
2. Настроить CI для зафиксированного npm: установка через `npm ci` по `package-lock.json`, затем type-check, oxlint, формат, Vitest, сборка и проверка пакета через соответствующие `npm run` scripts. Не включать автоматическую публикацию.
3. Запустить publint и `npm pack --dry-run --json`, затем собрать настоящий архив через npm pack в тестовый каталог.
4. Установить архив в отдельный чистый проект и в изолированную глобальную область/prefix. Проверить реальный bin, shebang, команды и runtime-зависимости без доступа к исходникам и devDependencies рабочего проекта.
5. Проверить содержимое архива: нужные dist/runtime-файлы, README, лицензии; без тестовых фикстур, локальных настроек агентов, временных данных и журналов.
6. Проверить обнаружение тестового скилла всеми пятью реальными агентами в выделенном тестовом проекте/изолированных конфигурациях. Отдельно подтвердить функциональность symlink; тест существования папки не заменяет проверку обнаружения агентом.
7. Проверить перенос проекта через Git: `.agents/skills`, корневой `skills-installer-lock.json`, прямые подключения и относительные ссылки, executable и стабильность хеша. Рабочие каталоги и файлы блокировки/временного lock исключены, ресурсы внутри скиллов сохраняются. Проверить совместное присутствие Vercel skills-lock.json без изменения его содержимого. CLI не должен сам создавать пользовательские коммиты.
8. Завершить README: add и меню, автоматизация с -a, registry и find с выбором/установкой, версии/откат, общая версия, force, удаление без защиты, Git-сценарий, ограничения MVP и отключение статистики.
9. Проверить Changesets и записать ручной процесс подготовки версии/changelog. Автоматическое повышение версии и публикацию не запускать; окончательное npm-имя и публикация остаются отдельным решением.
10. Проверить лицензионные уведомления всего перенесённого кода, финальный diff и отсутствие новых возможностей вне плана.

## Итоговая матрица

| Группа        | Обязательные сценарии                                                                            |
| ------------- | ------------------------------------------------------------------------------------------------ |
| CLI           | Add работает; install не является командой/алиасом; help/version и ошибки аргументов             |
| Интерактив    | Три основных агента предвыбраны, все пять доступны, пустой выбор запрещён                        |
| Автоматизация | -a обходит меню; без TTY нужен -a; отмена не создаёт файлов/событий                              |
| Поиск         | Find: динамический ввод, прокрутка, выбор и установка, отмена обоих меню, без TTY только таблица |
| Источники     | Папка, tar.gz, tgz, registry latest и exact                                                      |
| Ресурсы       | Бинарные данные, executable, внешние ссылки, циклы и сломанные ссылки                            |
| Области       | Локальная/глобальная независимость, пути и env-переопределения                                   |
| Агенты        | Все пять отдельно и вместе, реальное обнаружение установленного скилла                           |
| Подключения   | Повтор, новый агент, частичный сбой, полный отказ без обновления существующей копии              |
| Версии        | Latest, exact, update, unpin через add, явный rollback через add                                 |
| Ручные правки | Защита перезаписи, force, удаление изменённой копии без защиты                                   |
| State         | Повреждённый lock, отказ записи, откат, параллельные процессы                                    |
| Registry      | Проверка digest/размера, истёкший URL, ошибки API и очистка временных файлов                     |
| Статистика    | Wire-install/operation-add, отсутствие умножения на агентов, отключение, ошибки endpoint         |
| Git           | Перенос относительных ссылок и хеша, сохранение исполняемого признака                            |
| Пакет         | Чистая установка настоящего npm-архива и запуск без devDependencies                              |
