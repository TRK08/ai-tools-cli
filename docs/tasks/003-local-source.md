# 003. Подготовка локальной папки

## Цель и входные условия

После аппрува 002 подготовить локальный скилл в самостоятельном временном каталоге с метаданными, идентичностью, contentHash и очисткой. Источник не знает об агентах. Требования — [SPEC.md](SPEC.md).

Из форка изучить `../../../skills/src/frontmatter.ts` и копирование ресурсов в `../../../skills/src/installer.ts`. Не переносить обработчик add или агентские преобразования файлов.

## Работы

1. Принимать папку с `SKILL.md` в корне. Проверять доступность каталога, frontmatter, `name` и `description`, допустимость имени как компонента пути.
2. Использовать YAML-парсер без исполняемых форматов. Сохранять исходное содержимое SKILL.md, не генерировать его заново из метаданных.
3. Скопировать ресурсы в отдельный временный каталог, сохранив бинарные данные и исполняемые права файлов.
4. Разыменовать внутренние и внешние файловые ссылки. Их цели копируются под соответствующим путём внутри скилла; исходные ссылки в подготовленной копии не сохраняются.
5. Обнаруживать циклы, сломанные и нечитаемые ссылки; отклонять специальные файловые объекты. Ошибка останавливает подготовку и очищает её временные данные.
6. Проверять, что целевые пути копирования находятся внутри подготовленного каталога. Не захватывать собственные временные файлы, хранилище и резервные копии CLI при источнике, содержащем проект.
7. Не менять пути в Markdown или скриптах. Внешний ресурс после копирования — обычная часть установленного снимка.
8. Вычислить contentHash готового снимка и вернуть подготовленный источник с функцией очистки. Хешируемый набор должен совпадать с устанавливаемым.

## Не входит

Установка ссылок агента, запись установки в lock, архивы, сетевые запросы, анализ зависимостей по тексту Markdown/кода.

## Критерии готовности

- [x] Подготовленная папка содержит инструкции и ресурсы с сохранёнными байтами и executable.
- [x] Внешний `scripts -> ../shared-scripts` становится обычной внутренней папкой scripts.
- [x] Вложенные ссылки и циклы обрабатываются предсказуемо, внешних файловых ссылок в результате нет.
- [x] Текст SKILL.md и скриптов не переписывается.
- [x] Источник и действующая установка не изменяются ни при успехе, ни при ошибке.
- [x] Все временные данные доступны для явной очистки и удаляются при сбое; ошибка самой очистки явно сообщается.

## Проверки

- Общие проверки из индекса.
- Минимальный скилл, бинарный ресурс, исполняемый скрипт, вложенные ресурсы.
- Нет SKILL.md, некорректный YAML, недопустимое имя, нет обязательных метаданных.
- Ссылки на внутренний/внешний файл и каталог, вложенная ссылка, цикл, сломанная цель.
- Изменение внешнего источника после подготовки не меняет уже подготовленный снимок.
- Источник в корне проекта не приводит к рекурсивному копированию хранилища CLI.
- Инъекция ошибки чтения/копирования: источник прежний, временные данные очищены.

Реализована подготовка одного локального скилла без установки и записи lock.
Результат одобрен пользователем, статус `approved`; реализация 004 не начиналась.

### Изменения

- `src/sources/directory.ts`: `prepareDirectory(source, options)` возвращает
  существующий контракт `PreparedSource`: готовую папку, метаданные, абсолютную
  лексическую идентичность, `version: null`, хеш и идемпотентный `cleanup`.
  Чтение/копирование выполняется последовательно через fd, с сохранением bytes и
  `mode & 0o777`, проверкой типа/dev/inode и размера файла. Hash считается по
  завершённой копии; метаданные читаются из её же SKILL.md.
- `src/sources/frontmatter.ts`: YAML core schema без исполняемых/custom tags;
  проверка обязательных строк и безопасного имени через State. Поддерживаются
  BOM/CRLF, многострочные строки, обычные aliases с лимитом 100; duplicate keys,
  некорректный YAML и неизвестные теги отклоняются. Файлы не переписываются.
- `src/sources/filesystem.ts`, `errors.ts`: подмена файловых операций для сбоев,
  коды ошибок и сохранение cause. Ошибка очистки сохраняет обе причины и путь.
- `tests/directory-source.test.ts`, `frontmatter.test.ts`: 70 новых тестовых
  сценариев, из них 69 прошли на macOS и один предназначен для Linux. Проверены
  ссылки на файлы/папки, вложенные и повторные aliases, циклы, broken links, FIFO,
  инъекции сбоев и сохранность исходника/предыдущей установки.
- [sources.md](../sources.md), [architecture.md](../architecture.md), корневой
  README: внутренний API, исключения и границы; индекс синхронизирован.

Для подготовки передаются абсолютный cwd и **существующая отдельная** база
временных данных. Адаптер не создаёт базу внутри исходника и не оставляет новую
папку при её отсутствии. Исключаются точные пути проектных установок и состояния, база
временных данных и дополнительные пути `excludedPaths`, включая их
symlink-цели. В последних вызывающий код может передать глобальное хранилище.
Ресурсы с совпадающими служебными именами вне исключённых путей сохраняются.

### Ограничения

Linux-матрица и тест имён с невалидными UTF-8 байтами не выполнены на macOS;
матрица относится к 011. Все обязательные сценарии 003 выполнены на macOS.
Подготовка не является атомарным снимком дерева, которое параллельно меняет
редактор; защита от конкурентной подмены всех промежуточных каталогов вне реализации.
Файловая система может заблокировать очистку — такой сбой сообщается с путём.
Новых продуктовых договорённостей или других известных заблокированных проверок нет.

Собранный CLI пока проверяет каркас 001; адаптер 003 вызывается напрямую. Полный
цикл через CLI относится к 004, установка настоящего npm-архива — к 011.
