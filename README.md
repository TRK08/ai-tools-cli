# @trof_r/skills-installer

CLI для установки скиллов из реестра пакетов ai-tools-core. Поддерживает Codex,
OpenCode, Cursor, Pi и Claude Code в текущем проекте и глобально. Команда npm-пакета
называется `skills-installer`, интерфейс на русском.

Требуются Node.js ≥22.20.0 и npm. Для разработки используется npm 11.19.0.
Поддержка Windows x64/NTFS проходит нативную приёмку. Проверенные сценарии и
ограничения перечислены в [матрице Windows](docs/windows-validation.md).

## Запуск

```sh
npm ci
npm run dev -- --help
npm run dev -- config set registry https://registry.example
npm run dev -- find document
```

Передавайте аргументы CLI после `--`. Для запуска в другом проекте выполните
`npm run build`, затем вызовите `node /absolute/path/to/ai-tools-cli/dist/cli.mjs`
из нужной папки. Установленный из npm-архива bin доступен как `skills-installer`.
В PowerShell при запрете запуска npm shim `.ps1` используйте `skills-installer.cmd`.

Базовый URL выбирается по порядку `--registry <url>`, `SKILLS_API_URL`,
`~/.skills-installer/config.json`. Без URL CLI показывает команду настройки.
`config set` проверяет и атомарно сохраняет URL без HTTP. Update берёт URL каждого
пакета из lock; смена настройки не переключает уже установленные пакеты.
Авторизации, login, токенов и cookies нет.

Повреждённую настройку можно заменить через `config set registry <url>` или
снять через `config unset registry`. Get и add/find без override показывают
путь повреждённого файла и команду исправления. Ссылки и каталоги вместо config
не перезаписываются.

## Команды

```sh
skills-installer config set registry https://registry.example
skills-installer config get registry
skills-installer config unset registry
skills-installer add document-tools --registry https://registry.example
skills-installer add document-tools --skill check-document compare-documents -p -a codex -y
skills-installer add document-tools@1.2.0 -g -a claude-code -y
skills-installer list -g
skills-installer update document-tools --skill check-document -y
skills-installer remove document-tools --skill check-document -p -a codex -y
skills-installer find document
```

- `add <package>[@version]` сначала получает и проверяет релиз, затем предлагает
  выбрать область, скиллы и агентов и показывает сводку. Отсутствующий пакет,
  версия или явно указанный скилл завершают команду до установочных вопросов.
  Все скиллы в меню отмечены. `--skill` принимает несколько имён, флаг можно повторить.
  Повторный add сохраняет прежний состав и подключения. Если версия меняется,
  установленный состав переходит на неё целиком. Точная версия позволяет откатиться.
  Следующий update проверяет текущий релиз. Чистый повтор выводит «Без изменений».
- `list` читает lock без сети и показывает пакеты, версии, скиллы и агентов. По умолчанию
  область проекта. `-a` оставляет скиллы, подключённые к указанным агентам.
- `update [package]` переводит установленный состав пакета и все его подключения на
  текущий релиз. Сначала выбирается область для чтения lock, затем проверяются
  релизы в сохранённых registry, после чего доступны меню обновлений и подтверждение.
  `--skill` с именем пакета проверяет, что скилл уже установлен.
  `-a` фильтрует пакеты. CLI показывает переход версии и удаляет скиллы, исчезнувшие
  из релиза. Новые скиллы можно добавить командой add. Без имени пакета интерактивное
  меню предлагает выбрать обновления, с `--yes` применяются все подходящие.
- `remove [package]` работает без сети. В меню можно выбрать пакет, скиллы и
  подключения, все предложенные скиллы и агенты отмечены. С `--yes` нужен пакет,
  а пустые фильтры означают весь его установленный состав и все подключения.
  Последнее подключение удаляет общую копию. После последнего скилла исчезает запись пакета.
- `find [query]` показывает имя скилла, пакет и версию. Интерактивный выбор устанавливает
  один скилл из показанного релиза через обычный add: точный релиз проверяется
  до вопросов об установке. Без TTY или с `--yes` нужен
  запрос от 3 символов после trim. Показываются до 10 самых популярных
  совпадений; лимит и сортировка фиксированы. CLI сохраняет серверный порядок, показывает
  найденное/отображённое количество и команды установки. В TTY debounce 200 мс;
  прежние запросы отменяются. Другие страницы автоматически не загружаются.

Для поиска нужен Core с поддержкой `sort=popular` в `/api/v1/components`.
Текущий контракт и код Core содержат эту сортировку; версия конкретного
развёрнутого реестра проверяется отдельно. CLI сохраняет серверный рейтинг.

| Параметр              | Назначение                                       |
| --------------------- | ------------------------------------------------ |
| `-p, --project`       | Текущий рабочий каталог                          |
| `-g, --global`        | Глобальная область пользователя                  |
| `-a, --agent <agent>` | Явный агент. Флаг можно повторить                |
| `--skill <name...>`   | Имена компонентов для add, update и remove       |
| `-y, --yes`           | Пропустить диалоги. Для add требуется явный `-a` |
| `--registry <url>`    | URL реестра для add и find                       |
| `--without-stat`      | Отключить статистику скачиваний и установок      |

Флаги `-p` и `-g` взаимоисключающие. Без них изменяющая команда предлагает область
в терминале и использует проект с `--yes`. Без TTY для изменения состояния
требуется `--yes`. В меню установки общая группа `codex`, `opencode`, `cursor`
и `pi` включена всегда, `claude-code` выбирается отдельно. Явный `-a` задаёт точный
список подключений. Общий каталог виден агентам независимо от отдельных записей.

## Файлы и состояние

| Область   | Общая копия                       | Lock                                   |
| --------- | --------------------------------- | -------------------------------------- |
| Проект    | `.agents/skills/<installName>/`   | `skills-installer-lock.json`           |
| Глобально | `~/.agents/skills/<installName>/` | `~/.agents/skills-installer-lock.json` |

Проектом считается текущий каталог. Имя установки задаёт `spec.installName` из
реестра. Claude Code получает относительный symlink в проекте на всех ОС.
Глобально используется symlink на macOS/Linux и junction на Windows.
Подробности и `CLAUDE_CONFIG_DIR` описаны в [Installer](docs/installer.md).

Перед заменой или удалением CLI показывает обнаруженные ручные правки.
Подтверждение и `--yes` разрешают их потерю. Чужие каталоги вызывают ошибку.
Изменения файлов и lock одного пакета откатываются вместе при ошибке применения.
Массовое обновление сообщает ошибки по пакетам и сохраняет успешные обновления.

Единственная схема lock — `version: 1`, с пакетами, версиями, хешами и связями
`direct/link`. Проектные пути относительные; путей пользовательского хранилища в lock нет.

Проверенные распакованные компоненты сохраняются в `~/.skills-installer/store/`.
Повторная установка в другом проекте или глобально использует запись после
проверки её содержимого. ZIP постоянно не хранится. `.agents` содержит обычные
независимые файлы: правки проекта не меняют хранилище и другие установки.
Метаданные всегда запрашиваются в registry; офлайн-режима и очистки хранилища нет.
`remove` сохраняет его записи. [Устройство хранилища](docs/store.md)

Add и update проверяют содержимое и связи при прежней версии: отсутствующие
файлы и ссылку Claude восстанавливают после подтверждения. Ctrl+C, SIGINT и SIGTERM
до записи lock отменяют подготовку или откатывают пакет. После записи lock пакет
сохраняется, очистка завершается, массовый update останавливается.

Общую копию, относительную ссылку Claude и lock можно перенести через Git.
На Windows для проектного Claude нужны разрешение создания symlink и корректный
checkout с `core.symlinks=true`. CLI Git-конфигурацию не меняет.
[Перенос проекта через Git](docs/state.md#перенос-проекта-через-git)

События `download` и `install` относятся к конкретному релизу и компонентам.
Повторное использование хранилища не отправляет `download`. Их можно отключить через `--without-stat`, `DISABLE_TELEMETRY=1` или `DO_NOT_TRACK=1`.
Ошибки доставки не меняют результат установки. Код 0 означает успех, отсутствие
изменений, отказ или отмену. Код 1 означает ошибку, включая ошибку одного пакета
при массовом обновлении.

Вне MVP находятся локальные источники, публикация, закрепление версий, зависимости
скиллов, restore.

## Разработка

```sh
npm run type-check
npm run lint
npm run format:check
npm run test:run
npm run test:e2e
npm run package:check
```

Тесты используют временные project/home, управляемые TTY-потоки и подменяемый HTTP.
E2E запускает собранный CLI и локальную модель Core по HTTP. После упаковки
`npm run package:smoke -- /absolute/path/package.tgz` проверяет установленный bin.
`npm run test:e2e` каждый раз собирает исходники и запускает тесты только после
успешной сборки. Фильтры Vitest передаются после `--`.
