# skills-installer

CLI для установки и управления скиллами AI-агентов. Рабочая папка — `ai-tools-cli`,
один npm-пакет на TypeScript/ESM для macOS и Linux, Node.js >=22.20.0.

Работают `--help`, `--version` и `add`/`update`/`list`/`remove` для Claude Code, Codex,
OpenCode, Pi и Cursor в проектной и глобальной областях. Для `add` можно явно
указать повторяемый `-a` или выбрать агентов в интерактивном терминале.
Источники — локальная папка, локальные `.tar.gz`/`.tgz` и собственный registry.
Доступен поиск `find` с карточкой выбранного скилла перед установкой. Проектный `restore`
исключён из MVP по поручению пользователя.
Команды и алиаса `install` нет.

Интерфейс CLI полностью на русском: справка, меню, подтверждения, таблицы,
результаты и ошибки. Имена команд, флаги, идентификаторы агентов и данные скиллов
сохраняются. Политики показаны как «Актуальная (latest)», «Закреплённая (exact)»
и «Локальная»; в файле состояния остаются `latest`, `exact`, `local`.

В задаче 002 реализован внутренний модуль [State](docs/state.md): переносимый lock,
пути двух областей, атомарная запись, исключение конкурентных писателей и SHA-256
содержимого. Модуль проверяется на временных корнях.

В задаче 003 реализована внутренняя [подготовка локальной папки](docs/sources.md):
проверка YAML, копирование ресурсов с разыменованием ссылок, contentHash готового
снимка и очистка. В задачах 004–005 подключён [цикл установки](docs/installer.md),
в 006 — подготовка локального архива через то же ядро, в 007 — [registry-клиент](docs/registry.md),
в 008 — update, пропуск неизменного скачивания и управление версиями через add.

## Установка: область, агенты и карточка

В репозитории есть готовый [demo](demo/README.md) со скриптом проверки. Для собственного скилла подготовьте папку с `SKILL.md`:

```markdown
---
name: demo
description: Demo skill
---

Инструкции для агента.
```

После сборки запускайте CLI из каталога проекта (путь к сборке — абсолютный):

```sh
node /path/to/ai-tools-cli/dist/cli.mjs add ./demo -a codex
node /path/to/ai-tools-cli/dist/cli.mjs add ./demo -a claude-code -a pi
node /path/to/ai-tools-cli/dist/cli.mjs add ./demo
node /path/to/ai-tools-cli/dist/cli.mjs list
node /path/to/ai-tools-cli/dist/cli.mjs list -a pi
node /path/to/ai-tools-cli/dist/cli.mjs remove demo -a pi
node /path/to/ai-tools-cli/dist/cli.mjs remove demo
```

`add` создаёт обычный каталог `.agents/skills/demo` и запись в корневом
`skills-installer-lock.json`. Codex, OpenCode и Cursor читают каталог напрямую.
Claude Code и Pi используют относительные ссылки. Локальная область —
текущий каталог; запуск локальной команды из home запрещён. `list` читает собственный
lock и показывает компактную таблицу: Скилл, Версия, Политика, Агенты.
Область и фильтр указаны в заголовке, в конце — число скиллов и
подключений. Пустой список и отсутствие совпадений фильтра имеют отдельные сообщения.
Вывод доступен без TTY и не запрашивает подтверждения. Длинные значения переносятся
по ширине терминала без обрезки; Unicode выравнивается по видимой ширине.
У `update`, `list` и `remove` отсутствие `-a` означает всех зарегистрированных агентов.

В TTY `add` сначала спрашивает область: **«Локально — текущий проект»**
или **«Глобально — для пользователя»**, локальная выбрана по умолчанию.
`-g`/`--global` сразу выбирает глобальную область и пропускает этот вопрос.
Затем без `-a` показывается выбор пяти агентов с отмеченными Claude Code,
OpenCode и Codex. Стрелки перемещают курсор, пробел переключает отметку,
Enter подтверждает. Нужен хотя бы один агент; явный `-a` пропускает только меню агентов.

После выбора CLI показывает карточку с именем/slug, фактической версией,
источником, областью, политикой, описанием, общим каталогом и таблицей полных
путей **только выбранных агентов**. Для registry также показываются подробное
описание этой версии, теги и число установок. Затем появляется «Установить?»;
по умолчанию выбрано **«Нет»**. `-y`/`--yes` пропускает только подтверждение,
карточка остаётся. `--force` не заменяет выбор и подтверждение.

Escape/Ctrl+C отменяет любой шаг, включая получение данных карточки, с кодом 0.
Отказ и отмена сохраняют установленное содержимое и lock и не отправляют события.
Registry-архив скачивается после согласия. Локальный источник подготавливается
один раз перед карточкой; его временный снимок очищается при отказе.
Показанная версия сохраняется даже при публикации новой во время подтверждения;
`add slug` остаётся latest, а `add slug@version` — exact. Повторная установка
тоже показывает карточку и спрашивает подтверждение.

Меню требуют TTY для stdin и stdout. В скриптах указывайте `-a <agent>` и `--yes`;
без `-g` область локальная. Например:

```sh
npm run dev -- add ./demo -a codex --yes
npm run dev -- add api-contract-check -g -a pi --yes
```

Предпочтения области и агентов не запоминаются.

Для глобальной области добавьте `-g`/`--global` к `add`, `update`, `list` или `remove`:

```sh
node /path/to/ai-tools-cli/dist/cli.mjs add ./demo -g -a claude-code -a codex -a opencode -a pi -a cursor
node /path/to/ai-tools-cli/dist/cli.mjs list -g
node /path/to/ai-tools-cli/dist/cli.mjs remove demo -g
```

Глобальные copy и lock находятся в `~/.agents/skills/<name>` и
`~/.agents/skills-installer-lock.json`; глобальная область независима от проекта
и доступна из home. Глобальные назначения Claude Code — `~/.claude/skills`,
OpenCode — `~/.config/opencode/skills`, Pi — `~/.pi/agent/skills`, Cursor —
`~/.cursor/skills`, Codex читает общую копию напрямую. `CLAUDE_CONFIG_DIR` заменяет
корень `.claude`, `XDG_CONFIG_HOME` — `.config`; проектные пути от env не зависят.
Для уже зарегистрированного подключения используется путь из lock.

Повторный `add` того же источника объединяет успешные подключения без дубликатов;
снятие отметки в новом меню сохраняет прежнего агента. Ручные правки
установленного содержимого блокируют замену; `add ./demo -a codex --force` разрешает
их перезапись. Чужая папка или ссылка в назначении остаётся конфликтом даже с force.
Перед заменой выводится список затрагиваемых агентов. Частичный успех сохраняет
успешные подключения и возвращает код 1. Отказ всех выбранных подключений сохраняет
прежнюю копию и lock; новая неиспользуемая копия удаляется.

`remove demo -a pi` после подтверждения снимает выбранное подключение. Общая копия остаётся до последнего
зарегистрированного агента; последнее удаление убирает и ручные правки без проверки хеша и `--force`.
Исходная папка или архив сохраняются. Снятие прямого подключения не скрывает общую копию от
Codex/OpenCode/Cursor, пока другие зарегистрированные агенты её используют.
Чужие объекты на месте ссылок не удаляются; успешные удаления сохраняются с кодом 1.
Успех и повтор без изменений — код 0.

Содержимое, lock и относительные проектные ссылки коммитьте вместе. Список агентов
в проектном lock — общая настройка проекта. При обрабатываемом сбое до
сохранения lock файлы откатываются. Конкурентный писатель получает ошибку занятой
области. Подробности восстановления и ограничения — в [docs/installer.md](docs/installer.md).

Постоянных tmp/backups нет. Временный `.agents/.skills-installer-work-*` содержит
снимок и резервную копию только во время операции и удаляется после её завершения.
При ошибке отката/очистки CLI сохраняет оставшиеся файлы и сообщает их путь.
Существующий Vercel `skills-lock.json` и незарегистрированные скиллы не изменяются.

## Удаление: выбор скиллов и подтверждение

```sh
npm run dev -- remove
npm run dev -- remove demo other
npm run dev -- remove -g -a pi
npm run dev -- remove demo -a pi --yes
```

Без имён `remove` показывает скиллы из собственного lock выбранной области
с учётом `-a`. Отметок заранее нет: стрелки перемещают курсор, пробел переключает
скилл, Enter завершает выбор. Нужен хотя бы один пункт; длинный список
прокручивается, одновременно видно до восьми вариантов. В строках — имя,
установленная версия либо «локальная» и затрагиваемые агенты.

Явные имена пропускают меню, повторы объединяются. Неизвестные имена и скиллы
без подходящих подключений пропускаются с пояснением. CLI показывает таблицу
Скилл/Версия/Агенты и один вопрос для всего списка; по умолчанию выбрано **«Нет»**.
Отказ, Escape и Ctrl+C до удаления сохраняют файлы и lock и дают код 0.
`-y`/`--yes` пропускает подтверждение, но сохраняет выбор без имён.

Оба диалога требуют TTY для stdin и stdout. В скриптах указывайте имена и
`--yes`, например `npm run dev -- remove demo other --yes`. Без `-g`
используется текущий проект; отдельного выбора области или агентов нет.
Без `-a` удаляются все показанные зарегистрированные подключения. Подключения,
добавленные во время диалога, сохраняются.

Пустой список завершает команду с кодом 0 без вопросов. Итоговая таблица
показывает результат каждого выбранного скилла. Ошибка одного не останавливает
остальные; частичный результат или ошибка дают код 1. Удаление не обращается к
registry и не отправляет статистику. `--all`, wildcard и дополнительные алиасы
не поддерживаются.

## Локальные архивы

Для архива действуют тот же выбор агентов, обе области, `--force`, `list` и `remove`:

```sh
tar -czf demo.tar.gz -C ./demo .
node /path/to/ai-tools-cli/dist/cli.mjs add ./demo.tar.gz -a codex -a pi
node /path/to/ai-tools-cli/dist/cli.mjs add ./demo.tgz -g
```

Первая команда упаковывает всё содержимое папки `demo`. Расширения
`.tar.gz` и `.tgz` обозначают один формат; для второго примера создайте или переименуйте
архив в `demo.tgz`. В корне архива нужен `SKILL.md`; также принимается единственная
внешняя папка с `SKILL.md` непосредственно внутри. Если `SKILL.md` есть в корне,
всё содержимое этого корня входит в скилл. Поиска на других уровнях нет.

Лимиты: архив 20 MiB, содержимое файлов 25 MiB, не более 1000 записей файлов и папок.
Пути проверяются после нормализации и применения PAX/GNU metadata; абсолютные
пути и любой компонент `..` отклоняются. Архивные symlink/hardlink, специальные
записи, дубликаты путей, повреждённые gzip/tar и незавершённые потоки дают ошибку.
Метаданные и padding имеют дополнительный предел; детали — в [Sources](docs/sources.md).

Бинарные ресурсы и исполняемые права файлов сохраняются. Подготовка завершается до
замены установки; при ошибке прежние содержимое, подключения и lock остаются.
Lock хранит постоянный путь исходного архива и его SHA-256 отдельно от contentHash
подготовленной папки. Смена источника папка ↔ архив для одного имени требует remove/add.
ZIP и произвольный URL архива не поддерживаются.

## Registry

Для опубликованного скилла укажите slug или slug с полной SemVer-версией:

```sh
node /path/to/ai-tools-cli/dist/cli.mjs add api-contract-check -a codex -a pi
node /path/to/ai-tools-cli/dist/cli.mjs add api-contract-check@1.0.3 -g
node /path/to/ai-tools-cli/dist/cli.mjs add demo@1.2.3 --registry https://registry.example.test -a codex
```

Нужен работающий registry с выбранным опубликованным скиллом. URL выбирается в
порядке `--registry` → `SKILLS_API_URL` → `http://localhost:8000`. Разрешён HTTP(S)
base URL, в том числе с префиксом пути; credentials, query и fragment в нём запрещены.
Авторизация и `SKILLS_API_TOKEN` не используются. Выбор агентов, обе области,
`--force`, `list` и `remove` работают так же, как для локальных источников.

Существующий локальный путь имеет приоритет перед slug. Для однозначного локального
источника пишите `./demo`; `.tar.gz`/`.tgz` остаются локальными даже при отсутствии
файла. Версия должна быть полной, без `v` и диапазонов; prerelease/build разрешены,
например `demo@1.2.3-rc.1+build.2`. Один slug означает политику `latest`, точная версия —
`exact`; lock всегда хранит фактически полученную версию, исходный registry и slug.

Клиент проверяет metadata, фактические размер и SHA-256 архива до распаковки,
затем имя из `SKILL.md` и все архивные ограничения. Запросы имеют тайм-аут 30 секунд,
архив ограничен 20 MiB. Истёкшая ссылка или ответ скачивания 401/403 допускают
однократное обновление URL для той же версии и тех же размера/digest.
Повторная ошибка останавливает установку. Подписанный URL и его query-параметры
не записываются в lock и не выводятся в обычных сообщениях ошибок.

Неудачная сеть, повреждённый архив или неверная идентичность сохраняют прежнюю
установку. Другой registry или другой тип источника того же имени требуют remove/add.
Для registry отправляются события скачивания и установки; подробности — ниже.
Если фактическая версия и SHA-256 архива совпадают с lock, а установленная копия
соответствует contentHash, повторный add/update запрашивает только metadata.
Архив не скачивается; чистый повтор сохраняет файлы, ссылки и lock. Добавление
нового подключения или восстановление отсутствующей ссылки также использует
проверенную общую копию. Отсутствующая или изменённая копия требует скачивания;
ручные правки разрешено заменить только с `--force`.

## Обновление, версии и откат

```sh
node /path/to/ai-tools-cli/dist/cli.mjs update
node /path/to/ai-tools-cli/dist/cli.mjs update demo
node /path/to/ai-tools-cli/dist/cli.mjs update -a codex -a pi
node /path/to/ai-tools-cli/dist/cli.mjs update demo -g --force
node /path/to/ai-tools-cli/dist/cli.mjs update --yes
node /path/to/ai-tools-cli/dist/cli.mjs add demo@1.1.0 -a codex
node /path/to/ai-tools-cli/dist/cli.mjs add demo -a codex
```

`update` без имени обрабатывает все подходящие записи выбранной области. Без `-a`
используются сохранённые агенты без меню их выбора. Фильтр `-a`
выбирает записи, содержащие хотя бы одного указанного агента; общая версия выбранной
записи обновляется для всех её подключений. Перед заменой выводится их полный список.
Неизвестное имя — ошибка; пустой набор или отсутствие совпадений фильтра — код 0.

Перед подтверждением CLI показывает строку таблицы с текущей и доступной версиями
и всеми затрагиваемыми агентами. Область указана в заголовке. Если обновление есть, в TTY появляется
подтверждение для каждого пакета; по умолчанию выбрано «Нет, пропустить». Стрелки выбирают
ответ, Enter подтверждает. Отказ пропускает пакет и продолжает остальные;
Escape/Ctrl+C останавливает оставшуюся обработку. Уже подтверждённые обновления
сохраняются. Registry-архив скачивается после подтверждения; выбранная версия
не меняется, если текущая версия registry сменилась во время вопроса.

Для автоматического подтверждения используйте `-y`/`--yes`. Без TTY и без этого
флага доступное обновление завершается ошибкой с подсказкой. `--force` сам по себе
не подтверждает обновление. После обработки выводится общая таблица «Скилл», «Текущая»,
«Доступная», «Результат», «Агенты» для всех проверенных скиллов: «Обновлён», «Актуален»,
«Закреплён (exact)», «Частично», «Ошибка», «Пропущен» или «Отменено». Версии в таблице соответствуют моменту проверки
перед обновлением. Отсутствие обновлений показывает обе совпавшие версии и
«Обновлений нет» без вопроса. Для локального источника версия обозначена «локальная»; для exact
актуальная версия не запрашивается и обозначена «не проверялась». Заголовки, диалоги и сообщения
оформлены Clack, разбор команд — Commander.

Registry с политикой `latest` обновляется из исходного URL в lock; новый
`SKILLS_API_URL` его не меняет. У update нет `--registry`. `exact` пропускается
с объяснением, в том числе при `--force`. `add demo@1.1.0` выбирает указанную
версию, включая откат, и фиксирует `exact`. `add demo` снимает фиксацию и выбирает
текущую версию; для этих add укажите исходный registry через `--registry` или env,
если он отличается от default. Смена только политики для той же версии сохраняет
копию и меняет lock без скачивания. Другой источник того же имени требует remove/add.

Локальная папка и архив заново подготавливаются по сохранённому пути; обновляется
содержимое и хеши. Неизменный источник сохраняет установленную копию и lock.
Недоступный, повреждённый или переименованный скилл в источнике даёт ошибку,
прежняя установка сохраняется. Ручные правки блокируют замену без `--force`;
чужие назначения конфликтуют и с force. Пути подключений сохраняются из lock
после изменения настроек агентов в окружении.

По каждой записи выводится `Updated`, `Unchanged`, `Pinned` или `Error`; после
ошибки обработка остальных продолжается. Любая ошибка или частичный результат
даёт общий код 1. Каждая запись использует прежний механизм отката, весь пакет
обрабатывается под одной блокировкой области.

При запуске через npm обязательно ставьте `--` после имени script, чтобы npm
передал флаги CLI:

```sh
npm run dev -- add api-contract-check --global -a codex
npm run dev -- update api-contract-check --global
npm run dev -- update --global --yes
npm run dev -- remove api-contract-check --global
```

Без разделителя в `npm run dev add --global api-contract-check` флаг `--global`
получает сам npm, а CLI запускает проектную установку.

## Поиск и установка из registry

```sh
npm run dev -- find
npm run dev -- find api-
npm run dev -- find api- --global -a codex --registry http://localhost:8000
```

`find` в терминале открывает динамический поиск **по префиксу slug**.
Введите минимум два символа, например `api-`: после паузы 200 ms CLI запрашивает
`GET /api/v1/skills?slugPrefix=api-`. Фильтрацию выполняет backend; префикс
чувствителен к регистру, `%` и `_` считаются буквальными символами.
Необязательный префикс после find запускает первый запрос сразу, если содержит
минимум два символа.

Поле короче двух символов ждёт ввода без HTTP и очищает результаты. При изменении префикса старый
запрос отменяется, прежние варианты убираются из выбора; запоздалый ответ не меняет
результаты. Показываются загрузка, совпадения или ошибка API. При ошибке Enter
повторяет запрос; во время загрузки и без совпадений Enter не устанавливает скилл.
Можно исправить ввод Backspace/Delete, переместить курсор ←/→ или очистить поле Ctrl+U.

Стрелки ↑/↓ выбирают скилл, Enter подтверждает. Escape/Ctrl+C отменяют любую
стадию, включая ожидание сети. Показываются только slug@версия и число установок;
популярные идут первыми. Список
прокручивается, в окне до восьми вариантов. Значения переносятся по ширине;
слишком большой вывод ограничивается высотой окна с отметкой `…`.

После выбора идут область → агенты → карточка → подтверждение, как в add.
`-g` и `-a` пропускают свои меню, `--yes` — только подтверждение. `-a` задаёт агентов явно,
`--global`/`-g` выбирает область, `--force` разрешает замену ручных правок,
`--without-stat` отключает статистику. Отмена сохраняет существующую установку.
Find сохраняет политику **latest**: в поиске выбирается скилл, а не отдельная
версия. Для текущей операции устанавливается версия из подтверждённой карточки;
публикация новой версии во время выбора её не меняет. Последующий update проверяет
обновления. Повторный find снимает прежнюю фиксацию exact; явный `add slug@version`
по-прежнему закрепляет указанную версию.
URL выбирается так же, как в add: `--registry`, затем `SKILLS_API_URL`, затем
`http://localhost:8000`. Совпавшая локальная папка не меняет выбранный registry.

Без TTY `find <slug-prefix>` выполняет один такой же запрос и показывает таблицу
Slug/Версия/Установок без установки. Префикс короче двух символов — код 1
с подсказкой без HTTP.
Нет совпадений — код 0 и `Скиллы не найдены.`; ошибка API или сети — код 1.
Старая команда `search` заменена на `find`.

Описание выбранного скилла показывается в карточке установки add/find.
Сам поиск и просмотр карточки не отправляют события;
выбранная установка использует обычные download/install с operation add.

## Статистика registry

Registry-операции add/update отправляют v1-события на
`<исходный-registry>/api/v1/skills/events`. Update использует URL из lock,
даже если `SKILLS_API_URL` изменился. `SKILLS_TELEMETRY_ENDPOINT` заменяет endpoint
целиком. Авторизация отсутствует.

`download` отправляется после получения байтов и проверки размера/SHA-256.
Запрос metadata или подписанного URL не считается скачиванием. Если последующая
распаковка или установка не удалась, проверенное скачивание уже состоялось.
`install` отправляется по завершении установки со статусом success/partial/failed.
Один скилл и одна операция дают одно событие установки независимо от числа агентов.
Backend учитывает success/partial в накопительном счётчике, failed хранит без увеличения.
События содержат уникальный eventId, время, версию CLI, slug и URL registry,
операцию add/update, область, затрагиваемых агентов и версию скилла, когда определена.
Подписанные URL, пути локальных файлов и тексты ошибок не отправляются.

Повтор без изменений, смена только политики latest/exact, update закреплённой версии,
отказ/отмена и локальные источники не создают событий установки. Новое или
восстановленное подключение создаёт install; если общая копия целая, download нет.
Remove не отправляет события и не уменьшает счётчики.

```sh
npm run dev -- add api-contract-check -a codex --without-stat
npm run dev -- update --yes --without-stat
DISABLE_TELEMETRY=1 npm run dev -- add api-contract-check -a codex
DO_NOT_TRACK=1 npm run dev -- update --yes
```

`--without-stat` можно передать перед командой или после add/update/find. Любое непустое
значение `DISABLE_TELEMETRY` или `DO_NOT_TRACK` отключает отправку.
Каждая отправка ограничена одной секундой. Ошибка, неверный endpoint или тайм-аут
не меняют файлы, lock и код основной команды. Постоянной очереди, файлов событий
и повторных попыток доставки нет.

## Разработка

Используйте поддерживаемую чётную ветку Node: 22.20+ или 24.11+; npm зафиксирован
как `11.19.0` в `packageManager`. Требования сборщика отдельно от требований
готового CLI: [tsdown](https://tsdown.dev/guide/getting-started).

```sh
npm ci
npm run dev -- --help
npm run dev -- --version
npm run build
node dist/cli.mjs --help
```

`dev` запускает исходники через [загрузчик tsx](https://tsx.is/dev-api/) (`node --import tsx`), без отдельного
IPC-сокета tsx CLI; это работает и с длинным временным путём на macOS.
Аргументы CLI передаются script после `--`. Для изменения зависимостей используйте
`npm install --save-exact` и сохраняйте `package-lock.json`. Runtime-зависимости
Commander, Clack, fast-string-width, yaml и tar находятся в `dependencies`; инструменты сборки,
проверок и разработки — в `devDependencies`.

## Проверки

```sh
npm run type-check
npm run lint
npm run format:check
npm run test:run
npm run build
npm run package:check
```

Проверочные scripts не исправляют файлы. `npm run format` применяет форматирование
отдельно; `npm run test` запускает Vitest в режиме watch. `package:check` требует
предварительной сборки.

Тесты используют временные home/cwd/env, очищают их в `finally` и запрещают HTTP
по умолчанию. Дочерние процессы CLI получают то же изолированное окружение.
Реальные установки агентов не используются. Границы модулей и внутренние контракты
описаны в [docs/architecture.md](docs/architecture.md).

## Упаковка и изменения

```sh
npm run build
npm run package:check
npm pack --dry-run
```

Bin `skills-installer` указывает на `dist/cli.mjs` с shebang. В пакет входят только
`dist`, README и лицензионные файлы (а также обязательный `package.json`). Версия
встраивается из манифеста при сборке. Запуск готового CLI не требует исходников,
TypeScript или tsx; внешние зависимости устанавливаются npm из `dependencies`.
Выполнять build на машине разработчика, а не через install/prepare hook у потребителя.

`npm run changeset` добавляет заметку об изменениях. Повышение версии, changelog,
установка настоящего npm-архива и итоговая платформенная матрица относятся к задаче 011. Автоматических релизных hooks и scripts публикации нет. Публикация npm, push
и настройка remote требуют отдельного поручения.

Порядок задач и пользовательских аппрувов — в [docs/tasks/README.md](docs/tasks/README.md).
