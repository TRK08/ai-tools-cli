# Установка и подключения

[Installer](../src/installer/installer.ts) предоставляет `add`, `list`, `update`
и `remove` для одной области. Команды передают выбор и callbacks подтверждения.
Для add команда сначала разрешает релиз и проверяет явно запрошенные скиллы,
затем показывает меню области, скиллов и агентов. Ошибка registry или состава
завершает команду до этих вопросов; Installer получает уже проверенный релиз.
Installer строит план относительно текущего lock под блокировкой.

## Пути агентов

Имя каталога берётся из `spec.installName`. Тип подключения и путь задаёт
[каталог агентов](../src/agents/catalog.ts).
В проектном lock назначение link проверяется по `project.directory` конкретного
агента, находится внутри проекта и заканчивается именем установки. Link внутри
общего каталога запрещён; direct указывает на общую копию. Новое описание в
каталоге действует для всего цикла Installer и чтения/записи lock.

| Агент                       | Проект                                   | Глобально                        |
| --------------------------- | ---------------------------------------- | -------------------------------- |
| Codex, OpenCode, Cursor, Pi | `.agents/skills/`, общая копия           | `~/.agents/skills/`, общая копия |
| Claude Code                 | `.claude/skills/`, относительный symlink | `~/.claude/skills/`, ссылка      |

Глобальный Claude учитывает `CLAUDE_CONFIG_DIR`, относительный путь вычисляется
от cwd. При смене окружения сохранённая запись продолжает использовать путь из lock.
Проектная ссылка — относительный directory symlink на всех ОС. Глобальная ссылка
создаётся как POSIX symlink или Windows junction. Ошибка создания ссылки откатывает
пакет; обычная копия взамен ссылки не создаётся.
Даже при выборе только Claude общая копия существует. Снятие прямой связи из lock
не скрывает общий каталог от агента, пока остаются подключения к скиллу.

## План и подтверждение

У пакета одна версия в области. Add объединяет прежний состав и явный выбор.
При смене версии прежние скиллы, сохранившиеся в релизе, переходят вместе со всеми
подключениями. Исчезнувшие компоненты отмечаются в сводке и удаляются.
При update фильтры выбирают пакет, а содержимое определяет установленный состав.
После удаления последнего скилла запись пакета исчезает. Другие пакеты массового
обновления обрабатываются независимо.

Installer проверяет принадлежность каталогов и цель зарегистрированных ссылок.
Хеш общей копии сверяется с lock. Ссылка Claude проверяется по цели. Сводка показывает
изменённые копии, которые будут заменены или удалены. Подтверждение или `--yes`
разрешают эти потери. Отказ и отмена оставляют установленное состояние.
Повтор add того же релиза с целыми копиями и теми же связями не скачивает ZIP
и не переписывает lock. Отсутствующая ссылка Claude восстанавливается на проверенную общую копию.

Remove снимает выбранные подключения. Общая копия остаётся, пока у скилла
есть хотя бы одна связь. List и remove используют только локальное состояние.

## Транзакция

`StateStore.transaction` удерживает блокировку области до применения, отката
и очистки. Подтверждение строится по тому же lock, что и план. Для пакета
`FileTransaction` создаёт временную базу `.agents/.skills-installer-work-*`.
В неё копируются проверенные записи [хранилища](store.md). ZIP при промахе
подготавливается в пользовательском хранилище, затем удаляется из памяти. Подготовка завершается
до первой мутации. Перед заменой или удалением Installer повторно сверяет
состояние пути со сводкой, в том числе хеш и файловую идентичность объекта.

Перемещения и операции со ссылками имеют обратные операции. Глобальная ссылка
снимается без rename, поэтому каталог Claude может находиться на другом томе.
Сначала применяются файлы, затем атомарно записывается lock. При ошибке до
записи файлы откатываются в обратном порядке. Ошибка очистки после commit
сообщается отдельно. При неудачном откате сохраняется workspace для восстановления.
Единый сигнал команды проходит через HTTP, хранилище, распаковку, хеширование и
изменяющие операции. Ctrl+C/SIGINT/SIGTERM до commit останавливают подготовку
или запускают откат. Откат, удаление своих временных файлов и освобождение блокировок
не используют отменённый сигнал. После атомарного rename lock пакет завершён;
очистка продолжается, следующие пакеты update не начинаются. Повторные сигналы
не запускают повторный откат. SIGKILL и сбой питания не покрываются.

Пустые родительские каталоги могут остаться. Crash journal отсутствует. Оставшиеся
блокировки и recovery-каталоги диагностируются и автоматически не удаляются.
Блокировка защищает от других писателей CLI. Сторонние редакторы её не используют.

Дальнейшие детали описаны в [состоянии](state.md), [источниках](sources.md)
и [архитектуре](architecture.md).
