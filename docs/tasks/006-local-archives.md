# 006. Локальные архивы

## Цель и входные условия

После аппрува 005 добавить установку локальных `.tar.gz`/`.tgz` через существующее ядро и выбор агентов. Требования — [SPEC.md](SPEC.md). Исходная реализация для изучения: `../../../skills/src/download-source.ts` и связанные архивные тесты.

## Работы

1. Выделить распаковку локального архива независимо от HTTP-скачивания. Использовать согласованную библиотеку tar.
2. Поддержать `add ./demo.tar.gz` и `add ./demo.tgz`, с меню либо явным `-a`, локально и глобально.
3. Найти SKILL.md только в корне либо в единственной внешней папке. Корневой SKILL.md определяет корень скилла; произвольный рекурсивный поиск не выполнять.
4. Проверять нормализованные пути до извлечения. Запретить запись вне временного корня, абсолютные/восходящие пути, архивные symlink/hardlink и специальные записи.
5. Ограничить входной архив 20 MiB, распакованные файлы 25 MiB, количество файлов 1000; контролировать фактические байты и число записей в ходе обработки, а не только объявленные значения заголовков.
6. После распаковки использовать общую проверку метаданных/ресурсов и contentHash. Сохранять постоянный локальный путь архива как источник, отдельно от временного каталога.
7. Очищать временные данные при любой ошибке, не заменять действующую копию до завершения подготовки.
8. Обновить README и Changeset.

## Не входит

ZIP, произвольный URL архива, несколько скиллов в пакете, Git, скачивание и registry. Разыменование ссылок локальной папки из 003 не означает разрешение ссылок внутри архивов.

## Критерии готовности

- [x] Оба расширения и оба разрешённых расположения SKILL.md устанавливаются.
- [x] Используются общие агенты, состояния, защита правок и обработка частичного результата.
- [x] Архив не записывает ничего вне временного корня.
- [x] Повреждённые/слишком большие архивы, ссылки и отсутствие SKILL.md дают понятную ошибку.
- [x] Неуспешная подготовка не меняет действующую установку; временные файлы очищены. Отдельно проверен отказ самой очистки: ошибка сообщает workspace и обе причины, оставшиеся данные не объявляются удалёнными.

## Проверки

- Общие проверки из индекса; tar.gz и tgz с бинарным ресурсом и исполняемым скриптом.
- Корень и одна внешняя папка, отсутствующий SKILL.md, неоднозначные несколько внешних папок.
- Повреждённый gzip/tar, обрезанный поток, лимит входных и распакованных байтов, лимит файлов.
- Traversal, абсолютный путь, symlink, hardlink, специальная запись; файлы за пределами временного корня остаются нетронутыми.
- Неудачный архив поверх действующей установки: содержимое, ссылки и lock прежние.
- Одинаковое подготовленное содержимое папки и архива даёт одинаковый contentHash при одинаковых исполняемых признаках.

### Изменения

- [archive.ts](../../src/sources/archive.ts): отдельный адаптер `.tar.gz`/`.tgz` без HTTP, использующий `node:zlib` и `tar.Parser`. Проверка формата, путей, типов, лимитов и завершения потока предшествует созданию файлов. Метаданные и contentHash общие с папкой; бинарные байты и `mode & 0o777` сохраняются.
- [local.ts](../../src/sources/local.ts): выбор адаптера папки или архива; папки с суффиксом `.tgz`/`.tar.gz` продолжают поддерживаться. В [filesystem.ts](../../src/sources/filesystem.ts) добавлена подмена archive I/O для проверок ошибок.
- [Installer](../../src/installer/local.ts) поддерживает оба локальных источника через прежние транзакции, подключения и защиту правок. Lock сохраняет постоянный путь архива, `kind: archive` и archiveHash. В проекте путь относительный, глобально абсолютный. Перепаковка одинакового содержимого обновляет только digest, сохраняя inode установленной папки.
- [CLI](../../src/cli/program.ts): справка описывает оба источника; архив использует прежние `-a`, меню, `-g`, `--force`, list/remove. Команда `install` не добавлена.
- [README](../../README.md), [Sources](../sources.md), [Installer](../installer.md), [Changeset](../../.changeset/local-archives.md) обновлены. Зависимости и схема lock версии 1 не менялись.
- Новые проверки: [адаптер](../../tests/archive-source.test.ts), [установка](../../tests/archive-installer.test.ts), [CLI](../../tests/archive-cli.test.ts), [сырые tar-фикстуры](../../tests/helpers/archive.ts). Добавлено 89 тестов.

### Ограничения

- Один прежний тест имён с невалидным UTF-8 пропущен на macOS, как в 003–005. Linux-прогон и фактическое обнаружение агентами в этой задаче не выполнялись; итоговая платформенная матрица остаётся в 011. Это не заявляется пройденным.
- Node 22.20.0 в среде не установлен: собранный CLI фактически проверен на 22.23.2 и 24.21.0, target сборки — 22.20.
- Для metadata/padding bomb задан дополнительный предел всего tar-потока 29 MiB и отдельного metadata header 1 MiB. После EOF разрешён нулевой padding, ненулевые данные отклоняются. Файловые лимиты фиксированы, overrides через env отсутствуют.
- Сжатые данные и проверенные chunks распаковки буферизуются в памяти в пределах лимитов; отдельного archive cache нет. Аварийный обрыв процесса и конкурентные редакторы сохраняют прежние ограничения ядра; ошибка реальной очистки сообщает оставшиеся данные.
- ZIP, URL, registry, update/restore не реализовывались. Соседние проекты, существующие `.agents/`, `skills-installer-lock.json` и Vercel-lock пользователя не изменялись. Публикация, push и изменения remote не выполнялись.
