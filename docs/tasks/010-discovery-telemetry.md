# 010. Поиск, карточка и статистика

## Цель и входные условия

После аппрува 009 добавить поиск/карточку и учёт реальных скачиваний/установок registry. Требования — [SPEC.md](SPEC.md), контракт — `../../../ai-tools-core/docs/openapi/swagger.yaml`. В форке изучить `../../../skills/src/find.ts` и `../../../skills/src/telemetry.ts`, не переносить usage/hooks, JSONL-базу и общий код поиска с интерактивной установкой.

## Работы: поиск и карточка

1. Добавить `search <query>` и `info <slug>`, с тем же выбором registry, что в add. Авторизация отсутствует.
2. Search получает `GET /api/v1/skills`, фильтрует по slug, названию, описанию и тегам без учёта регистра. Все слова запроса должны присутствовать в совокупном тексте записи.
3. Показать slug, текущую версию и краткое описание; корректно различить пустой результат и ошибку API.
4. Info получает `GET /api/v1/skills/{slug}`, показывает описание, текущую и доступные версии. Не добавлять интерактивный выбор результатов поиска или JSON-вывод.

## Работы: статистика

1. Использовать существующий v1-envelope backend с уникальным eventId. Событие `install` не переименовывать в `add`.
2. Отправлять `download` после получения и проверки архива, `install` — по завершении операции со статусом success/partial/failed. Сохранять информацию об исходе даже при обрабатываемом исключении.
3. Контекст: операция add/update/restore, область, агенты, версия когда уже определена. Одно событие установки на скилл и операцию, а не по одному на каждого агента.
4. Endpoint по умолчанию брать из исходного registry записи/операции: `/api/v1/skills/events`. Поддержать переопределение SKILLS_TELEMETRY_ENDPOINT.
5. Поддержать `--without-stat`, DISABLE_TELEMETRY и DO_NOT_TRACK. Для локальных источников, интерактивной отмены и повтора без изменений события установки не отправлять. При новом подключении событие установки отправляется.
6. Не считать получение подписанного URL скачиванием. При пропуске скачивания не отправлять download. Удаление накопительные счётчики не уменьшает.
7. Ограничить HTTP-отправку коротким тайм-аутом; ошибки не влияют на результат, откат и exit code. Не создавать постоянную очередь или файл событий.
8. Обновить README и Changeset. Изменения backend и публикация не входят в задачу.

## Критерии готовности

- [ ] Поиск и карточка соответствуют реальному контракту.
- [ ] Ошибка сети не маскируется пустым каталогом.
- [ ] События отражают фактические действия для add/update/restore.
- [ ] Несколько агентов не умножают счётчик установок/скачиваний.
- [ ] `install` остаётся именем wire-события, `add` используется в operation.
- [ ] Отключение статистики, локальные источники и отмена не отправляют события.
- [ ] Ошибка статистики не меняет исход основной команды.

## Проверки

- Общие проверки из индекса; API-fixtures из текущего backend.
- Поиск без учёта регистра, несколько слов в разных полях, теги, пустой результат, ошибка API.
- Info с одной и несколькими опубликованными версиями, неизвестный slug.
- В тестовом HTTP-сервере проверить envelope, число событий и endpoint при registry override и сохранённом источнике.
- Success, partial, failed; несколько агентов; новый агент; повтор без изменений; update exact; восстановление без скачивания.
- Все способы отключения, локальные папки/архивы, отмена меню.
- Неверный ответ/тайм-аут endpoint: файлы, lock и exit code соответствуют основной операции, а не отправке статистики.
