# 004. Локальный цикл для Codex

## Цель и входные условия

После аппрува 003 получить первый рабочий цикл для Codex: `add ./demo -a codex`, `list`, `remove demo`. В этой задаче агент задаётся явно; полное меню и остальные агенты появляются в 005. Общие правила — [SPEC.md](SPEC.md).

Тестовую реализацию проверять в отдельном временном проекте с локальным скиллом `demo`. Корни файловой системы подменяются; реальные установки и пользовательские каталоги скиллов не затрагиваются.

## Работы

1. Подключить команды к Commander и внутренним операциям. Реализовать локальный add папки для Codex с явным `-a codex`, list по собственному состоянию и remove по имени.
2. Проверять идентичность источника и конфликт имени, назначение ссылки, допустимость операции. Существующая чужая папка/ссылка не заменяется даже с `--force`.
3. Использовать подготовленный источник из 003, общую копию `.skills-installer/skills/<name>` и относительную ссылку Codex `.agents/skills/<name>`. Сохранить агент `codex` и управляемое подключение в lock.
4. Повторный add того же источника использует прежнюю запись. Перед перезаписью сравнить фактический contentHash с эталоном; повторить проверку непосредственно перед заменой после долгой подготовки.
5. Реализовать `--force` только как разрешение заменить изменённую управляемую копию. Сохранить проверку источника и чужих назначений.
6. Подготовить новую копию полностью, временно сохранить старую, выполнить замену/подключение и записать lock. При обрабатываемой ошибке откатить изменения. После успеха убрать резервную копию.
7. Использовать блокировку области. Если не удалось ни одно запрошенное подключение, не обновлять прежнюю копию/lock; не оставлять новую копию без подключений.
8. List выводит установку из собственного состояния; повтор без изменений не создаёт дубликатов.
9. Remove проверяет принадлежность ссылки, удаляет её, общую копию и запись. Ручные правки не защищаются при удалении: без проверки хеша, подтверждения или требования `--force`. Исходник не удаляется.
10. Добавить описание работающих команд в README и Changeset для пользовательской функциональности. Не запускать version/publish.

## Не входит

Другие агенты, глобальная область, интерактивный выбор, архивы, сеть, update/restore и статистика. Временное ограничение явного Codex отражается в сообщениях до 005.

## Критерии готовности

- [ ] Команды работают из собранного CLI в отдельном временном проекте.
- [ ] Добавление создаёт одну копию, относительную ссылку `.agents/skills/demo` на неё и корректный lock с агентом `codex`.
- [ ] Повторный add обновляет управляемую копию без дубликатов.
- [ ] Ручные правки блокируют замену без `--force` и заменяются с ним.
- [ ] Ошибка подготовки, подключения или записи состояния сохраняет предыдущую рабочую установку.
- [ ] Remove удаляет изменённую копию без дополнительного подтверждения, но не трогает исходник/чужие объекты.

## Проверки

- Общие проверки из индекса и полный цикл через собранный CLI во временном проекте: `add ./demo -a codex`, `list`, `remove demo`.
- Проверить путь `.agents/skills/demo`, относительную цель ссылки и запись `codex` в lock; после remove ссылка, общая копия и запись удалены, исходная папка `demo` сохранена.
- Повторный add без изменений и после изменения исходника.
- Ручная правка установленного SKILL.md: отказ без force, успешная замена с force.
- Чужая папка и чужая symlink назначения; `--force` не обходит конфликт.
- Ошибка чтения источника, создания ссылки, замены и записи lock; проверить содержимое, ссылки и состояние после сбоя.
- Remove обычного и изменённого скилла, проверка сохранности исходника.
- Два процесса изменения одной области не повреждают состояние.
