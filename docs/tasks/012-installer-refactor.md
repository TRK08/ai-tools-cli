## Реализация

1. Перенести контракты в types; LocalInstaller → Installer, LocalInstallerOptions →
   InstallerOptions, LocalChange → InstallationChange. Обновить потребителей без алиасов;
   удалить неиспользуемый OperationResult.
2. Создать независимый каталог агентов: id, label, пути, тип подключения по области,
   предвыбор. Тип AgentId, валидация, меню и справка производны от него.
3. Извлечь inspection: хеш, общая копия, родители и владение подключениями.
4. Выделить source для выбора/разрешения/подготовки источника и plan для чистого
   расчёта preview/InstallPlan. SourceSelection и InstalledSnapshot фиксируют входные данные.
5. Выделить apply: файловые изменения и сохранение lock без сети и диалогов;
   повторная проверка владения/хеша перед мутациями. Выделить events для registry-событий.
6. Подключить фасад и install-координатор; сохранить последовательные пакеты update,
   list/remove, действующие StateStore и FileTransaction. Новые функции документировать на русском.

InstallPlan различает unchanged, metadata-only и apply, фиксирует источник/версию,
политику, прежнее состояние, подключения и prepared/reuse-содержимое. Фактические
статусы и признаки изменений определяются результатом применения.

Сохранить подтверждение registry до скачивания, однократный локальный снимок до
диалога, выбранную версию, latest/exact, повтор без загрузки/workspace, границы блокировки,
partial и откат при полном отказе подключений, все условия событий.
R1 принят пользователем; регрессии R2/R3 сохраняются. Производительность update,
параллельность, публичный SDK и новые зависимости не входят в задачу.

FileTransaction владеет workspace; адаптеры размещают временные ресурсы внутри
переданной базы. Прямые потребители PreparedSource вызывают cleanup самостоятельно.
Заимствованная установленная копия не очищается как временная. Ошибка до commit
откатывает файлы; ошибка очистки после commit не откатывает; ошибка rollback сохраняет recovery.
