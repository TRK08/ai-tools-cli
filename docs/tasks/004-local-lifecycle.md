# 004. Локальный цикл для Codex

## Цель и входные условия

После аппрува 003 получить первый рабочий цикл для Codex: `add ./demo -a codex`, `list`, `remove demo`. В этой задаче агент задаётся явно; полное меню и остальные агенты появляются в 005. Общие правила — [SPEC.md](SPEC.md).

Тестовую реализацию проверять в отдельном временном проекте с локальным скиллом `demo`. Корни файловой системы подменяются; реальные установки и пользовательские каталоги скиллов не затрагиваются.

## Работы

1. Подключить команды к Commander и внутренним операциям. Реализовать локальный add папки для Codex с явным `-a codex`, list по собственному состоянию и remove по имени.
2. Проверять идентичность источника и конфликт имени, назначение ссылки, допустимость операции. Существующая чужая папка/ссылка не заменяется даже с `--force`.
3. Использовать подготовленный источник из 003, общую копию `.skills-installer/skills/<name>` и относительную ссылку Codex `.agents/skills/<name>`. Сохранить агент `codex` и управляемое подключение в lock.
4. Повторный add того же источника использует прежнюю запись. Перед перезаписью сравнить фактический contentHash с эталоном; повторить проверку непосредственно перед заменой после долгой подготовки.
5. Реализовать `--force` только как разрешение заменить изменённую управляемую копию. Сохранить проверку источника и чужих назначений.
6. Подготовить новую копию полностью, временно сохранить старую, выполнить замену/подключение и записать lock. При обрабатываемой ошибке откатить изменения. После успеха убрать резервную копию.
7. Использовать блокировку области. Если не удалось ни одно запрошенное подключение, не обновлять прежнюю копию/lock; не оставлять новую копию без подключений.
8. List выводит установку из собственного состояния; повтор без изменений не создаёт дубликатов.
9. Remove проверяет принадлежность ссылки, удаляет её, общую копию и запись. Ручные правки не защищаются при удалении: без проверки хеша, подтверждения или требования `--force`. Исходник не удаляется.
10. Добавить описание работающих команд в README и Changeset для пользовательской функциональности. Не запускать version/publish.

## Не входит

Другие агенты, глобальная область, интерактивный выбор, архивы, сеть, update/restore и статистика. Временное ограничение явного Codex отражается в сообщениях до 005.

## Критерии готовности

- [x] Команды работают из собранного CLI в отдельном временном проекте.
- [x] Добавление создаёт одну копию, относительную ссылку `.agents/skills/demo` на неё и корректный lock с агентом `codex`.
- [x] Повторный add обновляет управляемую копию без дубликатов.
- [x] Ручные правки блокируют замену без `--force` и заменяются с ним.
- [x] Ошибка подготовки, подключения или записи состояния сохраняет предыдущую рабочую установку.
- [x] Remove удаляет изменённую копию без дополнительного подтверждения, но не трогает исходник/чужие объекты.

## Проверки

- Общие проверки из индекса и полный цикл через собранный CLI во временном проекте: `add ./demo -a codex`, `list`, `remove demo`.
- Проверить путь `.agents/skills/demo`, относительную цель ссылки и запись `codex` в lock; после remove ссылка, общая копия и запись удалены, исходная папка `demo` сохранена.
- Повторный add без изменений и после изменения исходника.
- Ручная правка установленного SKILL.md: отказ без force, успешная замена с force.
- Чужая папка и чужая symlink назначения; `--force` не обходит конфликт.
- Ошибка чтения источника, создания ссылки, замены и записи lock; проверить содержимое, ссылки и состояние после сбоя.
- Remove обычного и изменённого скилла, проверка сохранности исходника.
- Два процесса изменения одной области не повреждают состояние.

### Демонстрация собранного CLI

Выполнена командой `node --import tsx /private/tmp/ai-tools-cli-004-demo.mjs`.
Вспомогательный сценарий вне репозитория создавал отдельный временный проект,
вызывал абсолютный `dist/cli.mjs` через Node и проверял файлы после каждой команды;
проект и home удалены в finally. Запуск исполняемой сборки не использует tsx.
Основной сценарий воспроизводится по примеру в корневом README:

```sh
node /absolute/path/ai-tools-cli/dist/cli.mjs add ./demo -a codex
node /absolute/path/ai-tools-cli/dist/cli.mjs list
node /absolute/path/ai-tools-cli/dist/cli.mjs remove demo
```

Фактически проверено:

- Ссылка имеет цель `../../.skills-installer/skills/demo`, в lock один агент codex
  и одно подключение. List показывает `demo`, `local`, `codex`.
- Чистый повтор сообщает Unchanged; новый ресурс в источнике появляется в общей
  копии при повторном add, запись остаётся одна. До замены выводится codex.
- Ручная правка SKILL.md даёт код 1 и подсказку force; lock и правка сохраняются.
  С force возвращается содержимое источника.
- Ошибка подготовки после удаления исходного SKILL.md сохраняет установленную
  копию. После восстановления исходника remove удаляет ещё раз изменённую копию
  без force/подтверждения, ссылку и запись; исходник сохраняется.
- Чужая папка с контрольным файлом и чужая symlink остаются на месте после
  `add --force` с кодом 1; общая копия не создаётся. После устранения конфликта
  цикл add/remove проходит, tmp/backups пусты, operation.lock отсутствует.

### Откат и проверенные сбои

Инъекциями проверены ошибка чтения источника и YAML, создания symlink, переноса
старой копии в backup, переноса нового снимка, записи временного lock и его
атомарного переименования. Сравниваются точные старые байты lock, contentHash
прежней копии и цель ссылки. Для новой установки ошибки подключения/lock не
оставляют общей копии и ссылки; для существующей возвращают прежние файлы.
Force с последующей ошибкой lock сохраняет именно пользовательские правки.
Remove откатывает ссылку и изменённую копию при ошибках обоих rename и lock.

Отдельно проверены правки во время долгой подготовки и непосредственно перед
подключением, поздний чужой объект назначения, перенаправленные родительские
каталоги, конфликт источника, чужая общая копия и сохранение других записей.
Одна операция удерживает блокировку во время подготовки; конкурентный CLI-процесс
получает код 1/Scope is busy, после завершения повтор проходит без дубликатов.

После успешного commit ошибка очистки backup сообщает о сохранённой операции и
оставляет согласованные copy/lock. При дополнительной ошибке самого отката
сохраняются recovery-файлы и сообщается их путь; эти два ограничения также покрыты
тестами.

  macOS. Новый цикл на Linux и runtime Node 22.20 в этом запуске не проверялись;
  текущая проверка сборки и CLI выполнена на Node 24.21. Итоговая матрица — в 011.
- Обнаружение запущенным агентом не проверялось: проверены путь, относительная
  ссылка и содержимое; реальные каталоги агентов не затрагивались.
- Crash journal вне MVP. Блокировка исключает других писателей CLI, но не даёт
  атомарной защиты от произвольных внешних подмен между системными вызовами.
- Остальные агенты/глобальная область/меню — 005; архивы/сеть/update/restore и
  статистика не реализованы. Соседние проекты, существующие `.agents/` и
  `skills-lock.json` рабочего проекта не изменялись.
- На момент ревью коммит, push, remote и публикация не выполнялись. После аппрува
  пользователь поручил локальный коммит. Замечаний пользователя нет.
