# 007. Установка из registry

## Цель и входные условия

После аппрува 006 установить опубликованный скилл по slug или точной версии. Использовать [SPEC.md](SPEC.md), `../../../skills/src/registry-source.ts` и реальный контракт `../../../ai-tools-core/docs/openapi/swagger.yaml`.

Backend и его контракт в этой задаче не изменяются. Registry-клиент — внутренний модуль без UI, пригодный для будущего выделения в библиотеку.

## Работы

1. Разобрать `slug` и `slug@version`, сохранив проверки slug и полного SemVer из подходящего кода форка. Локальные пути/архивы не должны ошибочно распознаваться как registry.
2. Вычислять URL в порядке `--registry` → `SKILLS_API_URL` → `http://localhost:8000`. Проверять HTTP(S)-адрес; не вводить авторизацию или SKILLS_API_TOKEN.
3. Получать метаданные через `GET /api/v1/skills/{slug}/artifact` и `?version=...`. Проверять соответствие ответа запросу: slug, версию, SHA-256, размер, формат и URL.
4. Разделить получение метаданных и скачивание: будущий update сможет сравнить версию/хеш до скачивания, restore — запросить точную записанную версию.
5. Скачивать с тайм-аутом и лимитом, проверить фактические размер и SHA-256 до распаковки. Передать архив в общую подготовку из 006.
6. При истечении URL получить новую ссылку для изначально разрешённой версии. Digest/размер не должны меняться; повторную попытку ограничить, не переходить на новый latest.
7. Проверить `name` из SKILL.md против запрошенного slug. Сохранить исходный registry, slug, фактическую версию, хеш архива и contentHash, но не подписанный URL.
8. Add без версии сохраняет latest, с версией — exact. Использовать собственную schema lock; Git-источники вне MVP.
9. Показать понятные ошибки отсутствующего скилла/версии, недоступности registry, некорректного ответа и повреждения артефакта, используя реальные ответы backend.
10. Обновить README и Changeset. Подготовить данные о фактическом скачивании для подключения событий в 010, пока события не отправлять.

## Критерии готовности

- [x] `add demo` и `add demo@1.2.3` работают с меню либо явным `-a`, в обеих областях.
- [x] В lock хранится постоянная идентичность, а не временный URL.
- [x] Истёкшая ссылка обновляется без смены выбранного артефакта.
- [x] Несовпадение размера, SHA-256, версии или имени отвергается до изменения установки.
- [x] Пользовательский registry сохраняется как источник будущих update/restore.
- [x] Отмена меню не обращается к registry; неудачная сеть не удаляет старую установку.

## Проверки

- Общие проверки из индекса; HTTP-тестовый сервер с ответами по реальному контракту.
- Latest, exact, приоритет URL, локальный источник против registry reference.
- 404 скилла/версии, 503, тайм-аут, неверный JSON/метаданные, неверный формат.
- URL истёк до скачивания, 401/403 скачивания, успешное обновление URL, изменённая идентичность при refresh, повторно истёкший URL.
- Несовпадение фактических размера/хеша и имени в SKILL.md; сохранность предыдущей установки.
- Несколько агентов и обе области; секретные/временные query-параметры URL не попадают в lock.

### Изменения и внутренние контракты

- [RegistryClient](../../src/registry/client.ts): отдельные `resolveArtifact(reference)` и `downloadArtifact(artifact)`. Транспорт и тайм-аут подменяемы; UI/Installer/State не используются клиентом. Контракт сверён с `../ai-tools-core/docs/openapi/swagger.yaml` и HTTP handlers: 404 `not_found`, 503 `service_unavailable`, сообщения Skill or version not found / Service temporarily unavailable.
- [reference.ts](../../src/registry/reference.ts), [errors.ts](../../src/registry/errors.ts): slug, полный SemVer с prerelease/build, нормализация HTTP(S) base URL и понятные ошибки. Приоритет `--registry` → context.env.SKILLS_API_URL → localhost:8000; credentials/query/fragment base URL запрещены, SKILLS_API_TOKEN не используется.
- Metadata ограничена 64 KiB; проверяются JSON/UTF-8, slug, точная версия, нижний SHA-256, целый размер 1–20 MiB, tar.gz, URL и expiresAt. Скачивание ограничено 20 MiB по фактическим chunks; размер/digest сверяются до передачи в распаковку. Запросы имеют тайм-аут 30 секунд, включая тело; redirect запрещён, credentials не передаются.
- Истёкший expiresAt либо 401/403 скачивания дают один refresh исходной фактической версии. Digest/размер менять нельзя; slug/version/format также проверяются. Повторная ошибка или новый истёкший URL завершают операцию. Latest не запрашивается повторно для refresh.
- [registry.ts](../../src/sources/registry.ts) использует общую подготовку архивов из 006; проверяет имя SKILL.md и сохранность archiveHash при подготовке. Временный архив и снимок принадлежат одному workspace; прямому вызову доступен cleanup. Подписанный URL в PreparedSource не возвращается.
- [local.ts](../../src/sources/local.ts) сохраняет приоритет существующих локальных путей, включая сломанные symlink; явные пути и суффиксы архивов не становятся registry. [Installer](../../src/installer/installer.ts) использует прежнее ядро пяти агентов, обеих областей, защиты правок, частичного результата и отката. Для известного slug конфликт источника и ручные правки проверяются до HTTP. Имя LocalInstaller сохранено для совместимости с 004.
- [CLI](../../src/cli/program.ts) добавляет `add slug`, `add slug@version`, `--registry`. Отмена Clack предшествует определению источника и HTTP. List/remove работают с registry-записями без сети. Команды install, update, restore, search, info не добавлены.
- Lock версии 1 сохраняет исходный registry, slug, фактическую version, latest/exact, archiveHash и contentHash. [Schema](../../src/state/schema.ts) дополнительно проверяет slug, полный SemVer и совпадение slug с именем записи. URL скачивания и временный путь архива не сохраняются.
- `RegistryDownload` содержит registryUrl, slug, version, archiveHash и фактический size. Он возвращается клиентом, адаптером и результатом Installer; `onDownload` вызывается после проверки скачивания. Данные подготовлены для 010, событий сейчас нет.

Уведомление об адаптированных slug/SemVer из форка добавлено в [ThirdPartyNoticeText.txt](../../ThirdPartyNoticeText.txt). Зависимости и package-lock.json не менялись.

### Ограничения и границы задачи

- Один прежний тест имён с невалидным UTF-8 пропущен на macOS. Linux-прогон и фактическое обнаружение скилла агентами не выполнялись; платформенная матрица остаётся в 011. Это не заявляется пройденным.
- Node 22.20.0 не установлен; фактически проверены 22.23.2 и 24.21.0, target сборки — 22.20.
- Каждый add пока скачивает и готовит архив; пропуск неизменного скачивания и полный набор сценариев update/отката/снятия фиксации относятся к 008. Разделение metadata/download уже доступно.
- Байты ограниченно буферизуются в памяти; постоянного cache и crash journal нет. Ограничения конкурентных внешних редакторов и аварийного завершения у Installer прежние. Redirect, авторизация и arbitrary archive URL не добавлены.
- RegistryDownload — данные для 010, а не реализованная статистика. Update, restore, search/info и отправка событий не реализовывались. Собственная schema lock версии 1 сохранена.
- Существующие пользовательские `.agents/`, skills-installer-lock.json и skills-lock.json не менялись. Записи аппрува 006 были уже изменены в рабочей папке перед созданием ветки 007 и сохранены. До пользовательского аппрува коммит не выполнялся; push, remote и npm publish не выполнялись.
