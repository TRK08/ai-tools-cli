# 008. Обновление, версии и откат

## Цель и входные условия

После аппрува 007 реализовать update, политику latest/exact и явный откат через add. Использовать общую установку, не вызывать вложенный CLI. Правила — [SPEC.md](SPEC.md).

## Работы

1. Добавить `update [name]`, `-g`, повторяемый `-a`, `--force`. Без имени обрабатывать все подходящие установки; без `-a` использовать зарегистрированные подключения, без меню выбора агентов. По дополнению пользователя 2026-10-13: карточка текущей/доступной версии и подтверждение каждого обновления в TTY; `-y`/`--yes` для явного автоматического подтверждения.
2. Для latest запросить текущий артефакт исходного registry из lock. Для exact пропустить обновление с объяснением; force не снимает фиксацию.
3. При совпадающих версии и хеше и отсутствии необходимости замены не скачивать архив и не менять файлы. Сравнение метаданных отделено от получения содержимого.
4. Для локальной папки/архива заново подготовить сохранённый источник и сравнить contentHash. Недоступный источник — ошибка без удаления установки.
5. Применять новую копию через существующее ядро с защитой правок, откатом и сохранением подключений. Перед заменой показать всех затрагиваемых агентов.
6. `update -a codex` фильтрует скиллы, но не изолирует версию от других агентов той же копии.
7. `add demo@1.1.0` выполняет явный откат и сохраняет exact. `add demo` снимает exact и выбирает текущую версию; одинаковое имя из другого источника остаётся конфликтом.
8. Пакетный update продолжает остальные записи после ошибок; итоговый код 1 при любом сбое. Показать результаты по скиллам: обновлён, без изменений, зафиксирован, ошибка.
9. Обновить README и Changeset. Операционные результаты должны позволять 010 отличить реальные изменения от повторов.

## Критерии готовности

- [x] Latest обновляется из исходного registry; exact не обновляется обычным update или update --force.
- [x] Явный откат и снятие фиксации выполняются через add.
- [x] Неизменная установка не скачивается повторно без необходимости замены.
- [x] Обновление локальных источников работает и сохраняет установку при отсутствии исходника.
- [x] Общая версия обновляется для всех подключений, перечень затрагиваемых агентов виден пользователю.
- [x] Ручные правки защищены без force; ошибка одного скилла не прерывает остальные.

### Что изменилось

- `src/cli/program.ts`: `update [name]`, `-g`, повторяемый `-a`, `--force`; без имени — все совпавшие записи, без `-a` — сохранённые подключения без меню. Вывод Updated/Unchanged/Pinned/Error по каждой записи; partial/failed дают общий код 1 после обработки остальных.

Чистый повтор не создаёт workspace и не переписывает файлы/lock; смена только политики пишет lock. - `src/sources/registry.ts`: принимает уже разрешённые metadata, проверяет reference и скачивает выбранный артефакт без второго latest-запроса. Прежний refresh истёкшего URL остаётся привязанным к выбранной версии, размеру и digest.

### Проверенные сценарии и запросы

- Latest 1.0.0 → 2.0.0 из исходного registry, сохранение всех пяти подключений и путей после смены registry/Claude/OpenCode env; affected agents выводятся до замены. Один metadata-запрос и одно скачивание.
- Чистый add/update, включая force: **1 metadata-запрос, 0 скачиваний**, нет workspace, inode общей копии и байты/mtime lock сохраняются; callback download не вызывается. Exact update с/без force: **0 HTTP-запросов**, правки копии и lock сохраняются.
- Downgrade 2.0.0 → 1.0.0 через add сохраняет exact; add без версии возвращает latest 2.0.0. Смена latest ↔ exact на одной версии: только один metadata-запрос и запись политики в lock.
- При изменении только версии или только digest архив скачивается. Новые/отсутствующие ссылки создаются без скачивания. Отсутствующая копия, ручной файл или новая symlink внутри неё требуют получения архива; правки без force блокируют операцию до HTTP.
- Локальные папка/архив: неизменный, изменённый и исчезнувший источник; установка и подключения сохраняются при ошибках. Пакет продолжает следующие записи после отказа registry или локального источника, агентский фильтр оставляет другие записи без обновления.
- Force не перезаписывает чужие назначения или symlink вместо общей копии. При частичном результате сохраняются все желаемые подключения; новая копия доступна успешным агентам. Отказ всех подключений откатывает замену.
- Сбои rename/EXDEV, записи и commit lock возвращают прежнюю копию, включая принудительно заменяемые ручные правки; остальные записи пакета продолжаются. Workspace и блокировки убираются после успешного отката. Редактирование копии во время разрешения metadata защищено даже с force.
- Дочерние CLI-процессы проверяют коды 0/1, вывод результатов, ошибки имени/агента/лишних аргументов; управляемый TTY подтверждает отсутствие меню update.

### Актуальное поведение

- `src/cli/updates-ui.ts` оформляет update через имеющийся Clack: начало, карточка каждого скилла, Current version/Latest version, область, полный список агентов, состояние и итоговый счётчик. Commander продолжает разбирать команды и опции. Новых зависимостей нет.

Отказ пропускает конкретный пакет, Escape/Ctrl+C останавливает оставшуюся обработку; прежние подтверждённые записи остаются обновлёнными. - `-y`/`--yes` явно подтверждает изменения без вопроса, в том числе для скриптов. Доступное изменение без TTY и без `--yes` — ошибка с подсказкой до скачивания/применения. `--force` подтверждение не заменяет, `--yes` не разрешает перезапись ручных правок.
- В Installer добавлен callback `reviewUpdate(UpdatePreview)` и решения approve/decline/cancel. Ядро остаётся независимым от UI; прямой внутренний API без callback сохраняет автоматическое применение. Новые результаты skipped различают отказ и отмену. Подготовленный локальный снимок очищается при отказе/отмене.
- Metadata разрешается один раз; после вопроса загружается согласованный артефакт, даже если registry переключился на следующую версию. Владение и хеш повторно проверяются после ожидания пользователя. Восстановление ссылок и принудительная замена правок также запрашивают подтверждение.

### Диагностика глобальных команд

Предыдущее сообщение «Почему не работает глобальная установка/удаление/обновление ?» уточнено командой `npm run dev add --global api-contract-check`. На npm 11.19.0 изолированный script, печатающий argv, подтвердил:

- Без `--` после dev CLI получает только `add api-contract-check`, а npm получает `npm_config_global=true`.
- `npm run dev -- add --global api-contract-check` передаёт `--global` в CLI правильно.
- Отдельный прогон собранного CLI с локальной папкой и временным home выполнил глобальные add/list/update/remove для всех пяти агентов с кодом 0.

В README добавлены явные примеры для глобальных команд через npm и пояснение разделителя. Реальные глобальные установки при диагностике не изменялись.
