# 002. Состояние, пути и хеширование

## Цель и входные условия

После аппрува 001 реализовать общую основу хранения: области установки, переносимый lock, идентичность источников и `contentHash`. Основа — [SPEC.md](SPEC.md), особенно разделы о хранении и состоянии.

Задача 001 одобрена пользователем 2026-10-12: «Даю аппрув». Задача 002 начата по поручению «перейдем к 2 пункту плана». Работа ведётся в `task/002-state-paths-hashing` поверх локального коммита одобренной 001; `main` остаётся начальным основанием ветки 001.

Посмотреть `../../../skills/src/local-lock.ts` и `../../../skills/src/skill-lock.ts`. Старые схемы, молчаливое сбрасывание ошибок чтения и исключения из хеширования автоматически не переносить.

## Работы

1. Реализовать вычисление корней `.skills-installer` для текущего cwd и глобального home. Поиск корня Git не выполнять.
2. Ввести один версионируемый формат lock для двух областей с именем, источником, фактической версией, политикой, contentHash, хешем архива, агентами и управляемыми подключениями.
3. Хранить локальные источники относительно проекта, глобальные — абсолютно. Проектные подключения хранить переносимо; абсолютные пути текущей машины не должны протекать в проектный lock.
4. Проверять структуру и версию lock. Отсутствующий файл при чтении состояния отличать от повреждённого и от неизвестной схемы; вызывающая команда определяет, допустимо ли отсутствие. Запись выполнять через временный файл и атомарное переименование.
5. Зафиксировать постоянную идентичность источника отдельно от версии: смена версии registry не является сменой источника. Другой источник с тем же именем даёт конфликт.
6. Реализовать детерминированный SHA-256 по относительным путям, типам записей, байтам файлов и исполняемому признаку. Использовать стабильную сортировку без зависимости от локали и однозначное кодирование границ полей.
7. Хеш не зависит от абсолютного корня, владельца и mtime. Новые/удалённые/переименованные файлы, изменённый тип записи и chmod executable должны обнаруживаться.
8. Не следовать неожиданным ссылкам наружу при проверке уже установленной копии; такой объект должен отличаться от эталона, а не пропадать из расчёта. Для подготовленных источников ссылки уже будут разыменованы в 003.
9. Подготовить простой механизм исключения одновременных записей в одну область. Не добавлять журнал восстановления после аварийного завершения.
10. Настроить сохранение проектных skills/lock для Git и исключение только служебных временных файлов, резервных копий и блокировки CLI.

## Не входит

Чтение пакетов, создание агентских ссылок, команды update/restore и миграция состояния старого CLI.

## Критерии готовности

- [x] Проектная и глобальная области одного имени независимы; локальная область в home отклоняется по согласованному правилу, глобальная доступна.
- [x] Lock содержит все согласованные сведения и не содержит временных URL.
- [x] Перенос проекта сохраняет разрешимость путей и одинаковый contentHash.
- [x] Повреждение/неизвестная схема не превращаются в пустой lock.
- [x] Неудачная запись не уничтожает предыдущий корректный файл.
- [x] Изменения содержимого и исполняемого признака обнаруживаются; mtime не влияет.
- [x] Операции хеширования и записи работают на изолированных корнях.

## Проверки

- Общие проверки из индекса.
- Round-trip локального и глобального lock; относительные источники после переноса проекта.
- Отсутствующий файл, некорректный JSON, неполная запись, неизвестная схема.
- Инъекция ошибки записи/переименования: прежний lock читается без изменений.
- Бинарные данные, добавление/удаление/переименование, изменение executable, mtime, иной абсолютный корень.
- Неожиданная symlink внутри установленной копии не остаётся незамеченной.
- Конкурирующие записи одной области не теряют состояние; разные области независимы.

### Реализация и файлы

- `src/state/paths.ts`: точный cwd, глобальный home, пути lock/skills/tmp/backups/operation.lock, безопасность имени, переносимые источники и подключения, разрешение путей после переноса.
- `src/state/types.ts`, `schema.ts`, `errors.ts`: lock версии 1, строгая структура, поля записи, политики/хеши/агенты, уникальность управляемых путей между всеми записями, различие повреждения и неизвестной версии.
- `identity.ts`: постоянная идентичность источника независимо от версии/digest, нормализация registry base URL и конфликт смены источника существующего имени.
- `store.ts`, `mutex.ts`, `filesystem.ts`: чтение без создания состояния, атомарный rename после fsync временного файла, инъекция write/rename ошибок, очистка, блокировка всей операции и read-modify-write. Конкурентный процесс получает `SCOPE_BUSY`; другой home/cwd доступен независимо.
- `hash.ts`: детерминированный SHA-256, относительные пути/типы/bytes/executable, raw-byte сортировка, uint64BE длины полей, поток 64 KiB, symlink без обхода target, отказ на специальных записях и относительном корне.
- `.gitignore`, `tests/state-git.test.ts`: lock/skills/проектные ссылки сохраняются, служебные файлы игнорируются; ресурсы не теряются из-за общих правил или собственных вложенных каталогов `.skills-installer`.
- `tests/state.test.ts`, `tests/content-hash.test.ts`: переносимость, валидация, инъекции сбоев, конкурентные процессы, очистка, бинарные файлы, типы, chmod/mtime, внутренние/внешние/сломанные/циклические ссылки. Всего 46 новых тестов, вместе с 001 — 59.
- [docs/state.md](../state.md), README и архитектура описывают формат, API, семантику блокировки/ошибок и границы. Новых зависимостей нет; команды CLI последующих задач не добавлены.

### Согласованное правило и ограничения

Пользователь 2026-10-12 выбрал: **«Запретить локальную область в home (рекомендую)»**. SPEC уточнён: локальная область в home запрещена, глобальная остаётся доступной. `getStatePaths` отклоняет совпадение нормализованных путей с `PROJECT_IN_HOME`; перед чтением и захватом блокировки State проверяет dev/inode cwd/home и отклоняет symlink-алиас home. Отказ происходит до чтения/изменений состояния и не повреждает глобальный lock. Добавлены три теста; все критерии 002 закрыты.

Hash не является атомарным снимком произвольно изменяемого дерева; scope lock защищает CLI между собой, а не редакторы. Полная защита от конкурентной подмены промежуточных каталогов через openat здесь не реализована. После аварии operation.lock может остаться; автоочистки/журнала нет по границам MVP. Владельцы не включены в codec; реальная смена uid/gid не выполнялась (не требуется для тестирования исключённых полей).

Linux-матрица и установка настоящего npm-архива **не выполнялись**, относятся к 011. Backend, источники/frontmatter и создание подключений **не реализовывались и не проверялись**, относятся к последующим задачам. Остальных известных заблокированных проверок нет.
