# Registry

Клиент использует текущий контракт package/components ai-tools-core.
Для add/find URL выбирается из `--registry`, `SKILLS_API_URL`, затем сохранённого
`~/.skills-installer/config.json`. Без URL выводится подсказка `config set registry`.
Команды `config set/get/unset registry` работают без сети; set валидирует URL
и атомарно сохраняет его в подменяемом пользовательском корне. Авторизации,
login, токенов, cookies и заголовка Authorization нет.
Set/unset могут атомарно заменить повреждённый обычный config. Get и разрешение
registry без override сообщают о повреждении по-русски с путём и командами
исправления. Неверный новый URL, ошибка I/O и отмена до rename сохраняют прежние
байты; временный файл очищается. Ссылки, каталоги, специальные объекты и подмена
проверенного файла отклоняются. Ошибки доступа не считаются повреждением JSON.
Базовый HTTP(S) URL допускает путь reverse proxy. Учётные данные, query и fragment
отклоняются. Установленный пакет сохраняет нормализованный URL для update.

| Метод и путь                                                             | Использование                                       |
| ------------------------------------------------------------------------ | --------------------------------------------------- |
| `GET /api/v1/packages/{slug}`                                            | Разрешение текущего релиза либо точного `?version=` |
| `GET /api/v1/components?kind=skill&q=…&sort=popular&limit=10`            | Поиск скиллов по тексту в текущих релизах           |
| `GET /api/v1/packages/{slug}/components/skill/{name}/artifact?version=…` | Подписанный URL ZIP выбранного компонента           |
| `POST /api/v1/packages/{slug}/events`                                    | События точного релиза                              |

Клиент проверяет, что все компоненты ответа относятся к запрошенному пакету и
версии, имена уникальны, а `spec.installName` переносимо. Find принимает от 3 символов
после trim. В TTY debounce 200 мс, прежний HTTP отменяется, устаревший ответ
игнорируется. Более короткий запрос очищает выдачу без HTTP; без диалогов это ошибка.

Ответ поиска — страница `items/total/limit/offset`. CLI всегда передаёт
`sort=popular&limit=10`; пользовательских настроек сортировки и лимита нет.
Серверный порядок сохраняется, CLI показывает
найденное и отображённое количество без автоматической загрузки остальных страниц.
Выбранный результат устанавливается обычным add с показанной точной версией.
Add получает и проверяет метаданные релиза и явно указанный состав до вопросов
об области, скиллах и агентах. Ошибка HTTP, некорректный ответ, пустой состав или
отсутствующий скилл завершают установочный сценарий до меню. Этот GET одновременно
проверяет доступность пакета и возвращает релиз; отдельного запроса существования нет.
Если выбранный в find релиз исчез после поиска, установочные вопросы не открываются.

Контракт Core поддерживает `sort=popular`: сортировка по суммарному installCount
компонента по всем версиям по убыванию, затем по имени и slug пакета по возрастанию.
У компонентов без статистики число установок равно нулю. Фильтрация и сортировка
выполняются до ограничения страницы.
Для работы find нужен совместимый развёрнутый Core. Наличие этой сортировки
подтверждено соседними OpenAPI, реализацией и тестами; оно не подтверждает версию
или доступность конкретного сервера. Клиентской пересортировки и fallback на
другую сортировку нет.

Перед загрузкой идентичность, размер и SHA-256 ответа artifact сверяются с
выбранным релизом. При истёкшей ссылке или HTTP 401/403 клиент один раз запрашивает
новую ссылку для той же версии и проверяет её заново. Подписанный URL живёт
только в памяти. Скачанные байты ограничены 10 MiB и проверяются по размеру и
SHA-256. ZIP проходит отдельную проверку. [Источники](sources.md)

Клиент ограничивает время запросов и размер ответа. HTTP 404 и 410 отображаются
как отсутствие или блокировка релиза. CLI читает опубликованные версии.

Хранилище не заменяет получение метаданных релиза. Недоступный или заблокированный
релиз нельзя установить из локальной записи. Update всегда использует registry
из lock, независимо от новой настройки. List/remove не требуют registry или сети.
Поэтому update без явной области сначала спрашивает её, затем проверяет пакеты
из её lock. Меню обновлений и подтверждение следуют после получения релизов.
