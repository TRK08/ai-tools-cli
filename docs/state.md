# Состояние установок

[StateStore](../src/state/store.ts) получает абсолютные cwd/home через `getStatePaths`.
Локальная область — точный cwd, глобальная — home. Локальная область в home и его
symlink-алиасе запрещена до чтения/изменения состояния.

| Область   | Общая копия                | Lock                                   |
| --------- | -------------------------- | -------------------------------------- |
| Проект    | `.agents/skills/<name>/`   | `./skills-installer-lock.json`         |
| Глобально | `~/.agents/skills/<name>/` | `~/.agents/skills-installer-lock.json` |

Vercel `skills-lock.json` независим. `package-lock.json` фиксирует зависимости npm и не относится к установкам скиллов.

## Схема состояния

Lock содержит `version: 1` и словарь `skills`, ключ которого совпадает с `record.name`.
Принимается одна текущая форма без миграций и поддержки прежних установок;
неверная версия или структура дают `INVALID_LOCK`. Описание типов — в [types.ts](../src/state/types.ts), строгая проверка — в [schema.ts](../src/state/schema.ts).

| Поле записи         | Значение                                                                      |
| ------------------- | ----------------------------------------------------------------------------- |
| `source`            | directory/archive с постоянным `path` либо registry с `registryUrl` и `slug`  |
| `version`, `policy` | Registry: фактический SemVer и latest/exact; локальные адаптеры: null и local |
| `contentHash`       | SHA-256 подготовленного дерева                                                |
| `archiveHash`       | Обязателен для archive/registry, отсутствует у directory                      |
| `agents`            | Непустой список зарегистрированных/желаемых агентов                           |
| `connections`       | agent/path/kind; схема допускает подмножество agents                          |

Неизвестные поля, агенты и версии схемы, неверные имена/хеши/политики и конфликтующие
пути отклоняются. `kind` обязателен: direct/copy/link, значение сверяется с агентом
и областью через единый каталог. Claude использует copy в проекте и link глобально,
остальные агенты — direct. Один contentHash — эталон общей и всех агентских копий;
независимых версий или хешей агентов нет. Тип junction — деталь runtime Windows,
в глобальном lock сохраняется link. Прямые агенты одной записи могут разделять её общий каталог.
Имя не содержит разделителей/управляющих символов, не равно `.`/`..` и занимает до 255 UTF-8 байт.

Проектные источники и подключения сохраняются относительно cwd; источник может быть
снаружи (`../source`), подключение — только внутри. Глобальные пути абсолютны.
Идентичность локального источника лексическая: symlink не меняет её на путь цели.
Registry-идентичность — base URL + slug, без версии и временного download URL.
Смена источника уже существующего имени требует remove/add.

## Чтение, запись и блокировка

### Нативные пути и переносимые имена

Файловые операции используют нативные пути ОС. Проектные пути сохраняются с /;
глобальные остаются абсолютными нативными путями. У Windows-источника проекта
должен быть тот же диск, что у cwd; внешний путь на том же диске допустим.
Корни без диска, drive-relative, UNC/device и ADS отклоняются до resolve.

Модуль native-path использует обычный node:path текущей ОС. StatePaths хранит
только пути и область; выбора платформы в State, каталоге агентов и Installer нет.
Для тестов единственная зависимость модуля подменяется через createPathOperations
на path.win32 либо path.posix. Остальные модули получают те же операции без
дополнительных параметров. Формат проектного lock и пути записей tar всегда POSIX;
физические пути распаковки остаются нативными.

Сравнение Windows-путей учитывает регистр и локальный namespace-формат realpath,
не меняя строки для I/O и не заменяя лексическую идентичность источника на realpath.
Проверка вложенности выполняется по компонентам, включая разные диски.
Родители подключений проверяются последовательно нативными частями пути.
На POSIX сравнение остаётся чувствительным к регистру.

Имена скиллов проверяются по переносимым правилам Windows/POSIX: запрещены device
names, недопустимые символы, завершающие точки/пробелы и некорректный Unicode.
Коллизии имён записей lock по NFC/регистру запрещены. Общий валидатор имён также
принимает Buffer и отклоняет невалидный UTF-8 без переименования.

Правила путей проверяются отдельно через path.win32 на любой ОС; это не заменяет
нативную проверку Windows. Сценарии проектной копии Claude, junction и установленного
npm-пакета описаны в [проверках Windows](windows-validation.md).

### Атомарная работа с состоянием

- `read()` возвращает null только при первоначальном отсутствии корня/lock. Общий
  regular-file reader проверяет lstat/fstat/повторный lstat и точную BigInt identity.
  Подмена после проверки, symlink, специальный файл, повреждённый JSON и неверная
  схема дают ошибку; открытый handle закрывается до возврата.
- `transaction(callback)` удерживает `.skills-installer-operation.lock` рядом с lock;
  конкурентный писатель получает `SCOPE_BUSY`. Повторное использование завершённой транзакции запрещено.
- `write()`/`update()` валидируют и сортируют данные, записывают временный файл с `fsync`,
  затем заменяют lock через rename без предварительного удаления назначения. Ошибка
  до rename сохраняет прежний lock и удаляет временный файл; ошибка cleanup сохраняется
  вместе с исходной причиной.
- Mutex использует wx и удаляет только подтверждённый собственный обычный файл
  по BigInt dev/ino. Если fstat владельца не удался, объект остаётся; чужая замена
  не удаляется. Handle закрывается и при ошибке освобождения, причины сохраняются вместе.
- Оставшаяся после аварии блокировка не снимается автоматически. Блокировка State
  сама по себе не откатывает установки — это обязанность Installer/FileTransaction.

Внутри `transaction` используйте переданные `state.read`/`state.write`: самостоятельные
`store.write`/`store.update` попытаются захватить область повторно и получат SCOPE_BUSY.
Успешные записи пакета не откатываются целиком при поздней ошибке callback.

## Хеш содержимого

[hashDirectory](../src/state/hash.ts) вычисляет один текущий SHA-256 с marker
`skills-installer-content-v1`. Каждое поле предваряется восьмибайтовой длиной
big-endian. В хеш входят тип объекта, логический относительный путь с `/` и точные
байты файла; абсолютный корень используется только для I/O. Корневой каталог
имеет фиксированное представление directory с пустым путём.

Executable, остальные права, timestamps и owner игнорируются. Поддеревья только
из каталогов не влияют на хеш; непустые каталоги и пустые файлы учитываются.
LF/CRLF и изменения бинарных bytes меняют хеш, текстовой нормализации нет.

`portableNames` по умолчанию true: имена проверяются на переносимость и коллизии
NFC/регистра, хешируются и сортируются по NFC-байтам без localeCompare.
Физические имена не переписываются. false сохраняет сырые native POSIX-имена;
на Windows ограничения имён и коллизий остаются обязательными. Installer задаёт
одну политику из scope для подготовки источника и проверок установленной копии:
project — true, global — false. Прямой native POSIX-вызов требует явного false.

Ссылки включают собственный тип и target без чтения цели; подмена файла ссылкой
обнаруживается. Специальные объекты отклоняются. Общий regular-file reader проверяет
тип и точные identity, файл читается блоками 64 KiB с проверкой размера. Полной
защиты от конкурентной подмены каталогов и атомарного snapshot дерева нет.

`hashDirectory(directory, options?)` также принимает signal и узкий fileSystem
для тестов. Отмена проверяется между записями и блоками чтения; handle закрывается
до выхода. Совместный отказ чтения/отмены и close сохраняет обе причины.

Компонентные и интеграционные проверки состояния и хеширования перечислены
в [составе тестов](testing.md).
Переносите через Git lock, общий каталог и обычную проектную копию Claude вместе;
служебные work/lock/tmp
исключайте, сохраняя ресурсы внутри скиллов.

## Перенос проекта через Git

Закоммитьте обе обычные проектные копии и `skills-installer-lock.json` вместе.
В lock нет абсолютных проектных путей; глобальные установки и lock между машинами
не переносятся. После clone/checkout агенты читают копии сразу: CLI не создаёт
Git-коммиты, не меняет Git config и не требует post-clone команды.

До первого `git add` добавьте корневую `.gitattributes`:

```gitattributes
.agents/skills/** -text -filter -ident -working-tree-encoding
.claude/skills/** -text -filter -ident -working-tree-encoding
skills-installer-lock.json text eol=lf -filter -ident -working-tree-encoding
```

Если локальный source тоже хранится в Git, примените такие же byte-preserving
правила к его каталогу, например `skills/** -text -filter -ident -working-tree-encoding`.
Иначе source после checkout может отличаться от установленных копий.
Attributes действуют при добавлении/checkout и не восстанавливают уже потерянные
CRLF или бинарные bytes. Вложенная `.gitattributes`, `.git/info/attributes` и
пользовательские filters/ident/encoding могут переопределить корневые правила.
Проверяйте эффективные attributes ресурсов через `git check-attr`; вложенные правила
не должны включать преобразования. CLI не переписывает эти файлы внутри скилла.

Пример последних правил `.gitignore` после общих `node_modules/`, `dist/`, `*.tgz`:

```gitignore
**/.agents/.skills-installer-work-*/
**/.skills-installer-operation.lock
**/.skills-installer-lock-*.tmp
!**/skills-installer-lock.json
!**/.agents/skills/**
!**/.claude/skills/**
```

Нужен `**` у обоих деревьев: одного `*` недостаточно для глубоких ресурсов.
Исключения располагаются после общих правил и служебных имён: одноимённые файлы
внутри скилла остаются обычными ресурсами. Проверьте `git check-ignore --no-index`
и `git ls-files` после добавления; не применяйте общий `git add -f` к служебному workspace.

Проверка [Git roundtrip](../tests/integration/git-roundtrip.test.ts) входит в Vitest, использует
исходный CLI, настоящий локальный commit/clone на текущей ОС и `core.autocrlf=true/false`, `core.symlinks=false`.
Она сверяет bytes/hash, no-op без переписывания, защиту обеих копий и force,
работу list/remove без внешнего source и сохранность Vercel `skills-lock.json`.
Executable и исчезновение пустой папки при Git checkout не считаются ручной правкой;
изменённые bytes любой копии защищаются. Переход из старых установок не мигрируется:
принимается одна текущая схема 1 с `kind` и текущим hash marker.
