# Зафиксированные требования MVP

Этот документ сохраняет общие решения интервью и последнего плана. Порядок выполнения и аппрувов — в [README.md](README.md), согласованный стек — в [000-stack.md](000-stack.md). Изменения продуктовых правил сначала обсуждаются с пользователем.

## Цель и границы

Самостоятельный CLI `skills-installer` в `ai-tools-cli`, один npm-пакет на TypeScript/ESM для Node.js >=22.20, macOS и Linux. Новый установочный процесс, отдельные функции и тесты из `../skills`; контракт существующего `../ai-tools-core` сохраняется.

Менеджер пакетов проекта — npm. Зависимости фиксируются в `package-lock.json`, в CI устанавливаются через `npm ci`; scripts запускаются через `npm run <script>`. Этот lock-файл зависимостей отделён от состояния установленных скиллов.

Источники MVP: локальная папка, локальные `.tar.gz`/`.tgz`, собственный registry. Один пакет содержит один скилл. В каждой области одна активная версия одного имени. Локальная область — текущая директория, без поиска Git-root. Глобальная область независима.

Команды: `add`, `update`, `remove`, `list`, `restore`, `search`, `info`, `--help`, `--version`. Команды и алиаса `install` нет; одноимённое событие backend сохраняется.

Вне MVP: Git/well-known-источники, Windows, авторизация, usage/hooks, зависимости между скиллами, диапазоны версий, глобальный restore, миграция старых установок, кеш артефактов, публикация скиллов, интерактивный поиск, JSON-вывод, самостоятельные бинарники. Публикация npm-пакета — отдельное действие.

## Выбор агентов и CLI

Поддерживаются `claude-code`, `codex`, `opencode`, `pi`, `cursor`.

- `add <source> -a <agent>` использует явно указанных агентов без меню. `-a`/`--agent` повторяемый; повторы объединяются; неизвестное значение — ошибка.
- Без `-a` в интерактивном терминале показывается выбор всех пяти агентов. Предвыбраны Claude Code, OpenCode, Codex; Cursor и Pi доступны без отметки. Любую отметку можно снять; нужен хотя бы один агент.
- Стрелки — навигация, пробел — переключение, Enter — подтверждение. Отмена — код 0, без скачивания, изменения файлов и событий.
- Интерактив требует TTY для stdin и stdout. Без TTY и без `-a` — код 1 и подсказка указать агента; автоматической установки по предвыбору нет.
- Историю выбора, определение запуска внутри AI-агента, обязательных universal-агентов и дополнительные диалоги форка не переносим. Предвыбор фиксированный.
- Выбор завершается до скачивания и любых изменений установки. При повторном add существующие подключения сохраняются; снятие пункта в меню их не удаляет.
- `--global`/`-g` выбирает глобальную область. Для `update`, `remove`, `list` отсутствие `-a` означает все зарегистрированные подключения; меню не открывается.
- `update` без имени обрабатывает все подходящие записи. `remove` требует имя; массовой команды удаления нет.
- `restore` только проектный: без `-g`, `-a` и меню; восстанавливает общую конфигурацию из lock.
- Код 0 — успех/нет изменений/интерактивная отмена; код 1 — ошибка, включая частичную. Пакетные update/restore продолжают остальные скиллы после ошибки.

## Хранение и общая конфигурация проекта

Локально: `.skills-installer/lock.json` и `.skills-installer/skills/<name>/`. Глобально: `~/.skills-installer/` с той же структурой. Общая копия находится вне каталогов обнаружения агентов.

| Агент       | Локальный путь            | Глобальный путь                    |
| ----------- | ------------------------- | ---------------------------------- |
| Claude Code | `.claude/skills/<name>`   | `~/.claude/skills/<name>`          |
| Codex       | `.agents/skills/<name>`   | `~/.agents/skills/<name>`          |
| OpenCode    | `.opencode/skills/<name>` | `~/.config/opencode/skills/<name>` |
| Pi          | `.pi/skills/<name>`       | `~/.pi/agent/skills/<name>`        |
| Cursor      | `.cursor/skills/<name>`   | `~/.cursor/skills/<name>`          |

Глобальные пути Claude учитывают `CLAUDE_CONFIG_DIR`, OpenCode — `XDG_CONFIG_HOME`. Проектные подключения относительные. Выбор агента управляет его ссылкой, но не гарантирует исключительную видимость скилла только этому агенту.

Содержимое, lock и относительные проектные ссылки коммитятся вместе. Список агентов — общая настройка проекта. Глобальными установками управляет каждый разработчик отдельно. CLI не коммитит изменения автоматически. Временные файлы, резервные копии и блокировки не входят в проектную конфигурацию.

## State и хеши

Один версионируемый lock-формат для двух областей. Запись хранит имя, тип и постоянную идентичность источника, фактическую версию при наличии, политику `latest`/`exact`/локальный источник, `contentHash`, хеш архива при наличии, агентов и управляемые подключения.

Локальные источники в проектном lock — относительные пути, в глобальном — абсолютные. Проектные пути подключений переносимы. Registry-запись хранит исходный URL registry, slug, версию и хеши; подписанный URL не сохраняется.

`contentHash` детерминированно учитывает относительные пути, типы записей, байты файлов и признак исполняемого файла; не учитывает абсолютный корень, mtime и владельцев. Хешируется подготовленная копия после разыменования исходных ссылок. Хеш архива хранится отдельно. Изменённый тип записи/новая ссылка внутри установленной копии не должны незаметно пропускаться при проверке.

Повреждённый lock и неизвестная версия схемы — ошибка, а не пустое состояние. Запись атомарная. Одно имя уникально в области; другой источник того же имени — конфликт, смена источника через remove и add.

## Подготовка источников

Локальная папка содержит `SKILL.md` в корне. YAML frontmatter предоставляет `name` и `description`; имя проверяется для безопасного использования как имени каталога. Бинарные ресурсы и исполняемые права сохраняются.

Внешние и внутренние symlink в локальном источнике разыменовываются: их содержимое становится обычными файлами/папками внутри подготовленного скилла. Циклические и сломанные ссылки — ошибка. Markdown и скрипты не переписываются. Подготовка не изменяет источник и не захватывает собственные временные каталоги/хранилище CLI.

Для `.tar.gz`/`.tgz` принимаются `SKILL.md` в корне или в единственной внешней папке. Распаковка отделена от скачивания. Архивные symlink/hardlink и специальные записи отклоняются. Проверяются пути, количество файлов и размер. Базовые лимиты, совместимые с backend: архив 20 MiB, распакованные файлы 25 MiB, 1000 файлов. ZIP и поиск нескольких скиллов отсутствуют.

Подготовка завершается до замены общей копии; временные данные очищаются после успеха и ошибки. Адаптер возвращает подготовленную папку, идентичность, версию при наличии, хеши и очистку; он не знает об агентах.

## Установка, замена и удаление

Add/update/restore используют общее ядро без вложенных CLI-процессов. Повторный add того же источника переиспользует запись и объединяет подключения. Перед заменой показываются все затрагиваемые агенты.

- Перед перезаписью установленное содержимое сравнивается с эталоном lock. При отличии требуется `--force`. Коммит Git не меняет эталон; созданные скриптом файлы тоже считаются изменением.
- `--force` разрешает перезапись управляемой копии, но не чужих назначений, смену источника, снятие `exact` или обход проверки хеша источника при restore.
- Новая копия готовится полностью; прежняя временно сохраняется. Обрабатываемый сбой откатывает изменяемые файлы и состояние. Простая блокировка исключает параллельные изменения области; crash journal вне MVP.
- Если ни одно запрошенное подключение не удалось, прежние содержимое и lock сохраняются. Для новой установки без подключений общая копия удаляется.
- Если часть подключений успешна, сохраняется частичный результат и код 1. Новая общая версия используется всеми оставшимися подключениями.
- Remove удаляет выбранные управляемые подключения. Общая копия удаляется после последнего. Проверка хеша, `--force` и подтверждение удаления не нужны даже при ручных правках. Исходник не удаляется. Чужие объекты на месте ссылок не удаляются автоматически.

## Registry и версии

Приоритет URL: `--registry` → `SKILLS_API_URL` → `http://localhost:8000`. Авторизация и `SKILLS_API_TOKEN` вне MVP.

API: `GET /api/v1/skills/{slug}/artifact`, опциональный `?version=1.2.3`. Клиент проверяет идентичность, размер, SHA-256, формат и имя скилла. Истёкший URL обновляется для той же фактической версии; смена digest/размера при обновлении URL — ошибка.

- `add demo`: текущая версия и политика `latest`.
- `add demo@1.2.3`: указанная версия и `exact`.
- `update`: обновляет latest по исходному registry, exact пропускает с объяснением.
- `add demo@1.1.0`: явный откат и фиксация.
- `add demo` после фиксации: снятие фиксации и выбор текущей версии.
- Неизменные версия и хеш не требуют скачивания, если замена не нужна.
- Для локальных источников update заново подготавливает сохранённый источник и сравнивает содержимое. Недоступность источника не удаляет установку.
- `update -a codex` фильтрует записи, но обновление общей копии затрагивает всех её агентов.

## Restore

Существующая копия с нужным хешем используется без обращения к источнику. Отсутствующая копия восстанавливается из сохранённого источника. Существующая отличающаяся копия, включая частично удалённую, требует `--force` для замены.

Registry восстанавливается до фактической версии из lock независимо от latest. Локальный источник должен быть доступен и после подготовки совпасть с `contentHash`. Иначе ошибка по этому скиллу; остальные продолжаются. `--force` не отменяет совпадение хеша источника.

Восстанавливаются агенты из lock; неудача не удаляет желаемые подключения. Версия и политика обновления сохраняются. Чужие назначения не перезаписываются. Отсутствующий/повреждённый lock — ошибка до изменений; пустой корректный lock — нет изменений.

Restore возвращает оригинал установки по lock. Пользовательские правки, которые не являются этим оригиналом, восстанавливаются через Git.

## Поиск и статистика

Search получает `GET /api/v1/skills`, фильтрует slug, название, описание и теги без учёта регистра; все слова должны присутствовать в совокупном тексте. Выводит slug, текущую версию и краткое описание. Info использует `GET /api/v1/skills/{slug}` и показывает описание, текущую и доступные версии. Ошибка API не равна пустому результату.

События только для registry: `download` после получения и проверки архива; `install` со статусом success/partial/failed по результату операции. Одна установка = одно событие на скилл и операцию, независимо от числа агентов. Контекст: операция `add`/`update`/`restore`, область, агенты, версия когда определена. Backend-событие `install` не переименовывается в `add`.

Endpoint исходного registry: `/api/v1/skills/events`; переопределение через `SKILLS_TELEMETRY_ENDPOINT`. Флаг `--without-stat`, `DISABLE_TELEMETRY`, `DO_NOT_TRACK` отключают отправку. Ошибки отправки с коротким тайм-аутом не меняют исход команды.

Чистый повтор без изменений не увеличивает установки. Новое подключение — новая операция установки. Удаление счётчики не уменьшает. Постоянная очередь доставки, локальная база событий и статистика использования отсутствуют.

## Архитектура и завершение MVP

Модули: CLI, Sources, Registry client, Installer, State, Telemetry. CLI на Commander; интерфейс выбора на Clack. Бизнес-операции вызываются напрямую; HTTP и файловые корни подменяемы для тестов.

MVP завершается после проверенного и одобренного результата задачи 011: собранный npm-архив работает вне репозитория, сценарии источников/областей/агентов/версий/restore/ошибок проверены, обнаружение пяти агентами подтверждено, CI и документация готовы. npm-публикация не выполняется автоматически.
