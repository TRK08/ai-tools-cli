# @trof_r/skills-installer

## 0.3.0

### Изменения

- Переход на установку и управление пакетами скиллов из реестра ai-tools-core.

  #### Возможности
  - Команды `add`, `list`, `update` и `remove` работают с пакетами и их составом.
    Флаг `--skill` позволяет выбрать отдельные скиллы; `add <package>@<version>`
    устанавливает точную версию пакета. Обновление переводит весь установленный
    состав пакета и его подключения на одну версию, удаляя исчезнувшие скиллы.
  - Добавлены команды `config set/get/unset registry` для сохранения адреса реестра.
    Приоритет настроек: `--registry`, `SKILLS_API_URL`, пользовательский config.
    Обновление использует адрес реестра, сохранённый для каждого пакета в lock.
  - Поиск показывает до десяти самых популярных совпадений по запросу от трёх
    символов. Выбранный результат устанавливает конкретный скилл из найденного
    релиза. Реестр должен поддерживать `sort=popular` в `/api/v1/components`.
  - Добавлено общее локальное хранилище `~/.skills-installer/store/`: проверенные
    компоненты повторно используются между проектами и глобальными установками
    без повторного скачивания. Установленные файлы остаются независимыми копиями;
    для получения метаданных релиза по-прежнему нужен доступ к реестру.
  - Повторные `add` и `update` восстанавливают отсутствующие файлы и подключения,
    а повреждённые записи хранилища скачиваются заново. Изменения файлов и lock
    применяются с откатом в пределах одного пакета при ошибке или отмене до записи lock.
  - Добавлен явный выбор области `--project` / `--global`. Унифицированы меню,
    подтверждения и отображение результатов пакетных операций.

  #### Изменения совместимости
  - Установка из локальных папок и архивов `.tgz`/`.tar.gz` больше не поддерживается.
    Источником служит реестр пакетов; адрес `http://localhost:8000` больше не
    подставляется автоматически — реестр нужно настроить явно.
  - Lock теперь содержит массив `packages` вместо прежнего объекта `skills`.
    Номер схемы остаётся `1`, но старые lock-файлы несовместимы; автоматической
    миграции нет. Перед переходом сохраните ручные правки и переустановите скиллы
    из пакетов реестра.
  - Точная версия в `add` больше не закрепляет пакет: следующий `update` проверяет
    текущий релиз реестра. Флаг `--force` удалён; замена ручных правок разрешается
    подтверждением операции или `--yes`.
  - `--yes` пропускает диалоги; без явной области используется текущий проект.
    Для `add --yes` нужен `--agent`, для `remove --yes` — имя пакета. Команда
    `remove` принимает один пакет, а выбор его скиллов задаётся через `--skill`.
  - Claude Code в проекте использует относительную ссылку на общую копию скилла.
    На Windows нужны права создания symlink, а для переноса через Git — checkout
    с `core.symlinks=true`. Нативная приёмка Windows остаётся незавершённой.

  #### Внутренние изменения
  - CLI разделён на команды, представления и общие компоненты терминала;
    внутренние модули получили явные публичные API.
  - Обновлены интеграционные и сквозные проверки пакетных операций, хранилища,
    восстановления и отмены. `test:e2e` автоматически собирает CLI перед запуском.

## 0.2.1

### Patch Changes

- 8f65b2f: Улучшена переносимость CLI на Windows для Node 22.20/24: нативные пути, переносимые имена,
  изолированное окружение и запуск npm `.cmd`, глобальные junction и обычная
  проектная копия Claude. Обе проектные копии и lock переносятся через Git;
  CI проверяет Git commit/clone на Linux/macOS/Windows с сохранением bytes
  и один общий npm-архив на Node 22.20/24.

  Общие файловые операции и очистка ресурсов унифицированы. Тесты разделены на
  unit/integration/e2e; восемь сквозных сценариев проверяют собранный CLI с локальным
  registry и изолированными файлами. Повторные проверки перенесены к владельцам правил.

  Lock-файлы прежнего формата без connections.kind не поддерживаются. Поле
  connections.kind обязательно, contentHash учитывает bytes и NFC-пути, но не
  executable/пустые каталоги. Номер текущей схемы остаётся 1; миграций нет.
  Для существующих тестовых установок нужна переустановка с проверкой ручных правок.
  Нативная приёмка Windows обычным пользователем и обнаружение всеми агентами
  ещё не завершены; проверки CI не заменяют ручную приёмку.
