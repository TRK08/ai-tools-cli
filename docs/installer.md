# Цикл установки источников

`LocalInstaller` получает `RuntimeContext` с явными cwd/home/env/http и опции
`scope` (по умолчанию project), `fileSystem`, `store`, `prepare`, `report`, `registry`,
`registryClientOptions`, `onDownload`, `reviewUpdate`, `reviewAdd`, `signal`, `telemetry`. Имя класса сохранено для совместимости с 004;
в 007 он координирует также registry через то же ядро, в 008 — пакетный update.
Методы `add(source, force, agents)`, `addRegistry(reference, force, agents)`, `update(name?, force, agents)`, `list(agents)` и `remove(name, agents)`
вызываются Commander напрямую. Внутренний default `add` — Codex для совместимости
с 004; CLI всегда передаёт результат явного или интерактивного выбора.
Доступны локальные папки, `.tar.gz`/`.tgz`, registry, пять агентов и две области.
Restore исключён из MVP по поручению пользователя 2026-10-13.

AddResult также допускает skipped с reason declined/cancelled; отказ и отмена
не считаются failed и не отправляют события. Без reviewAdd внутренние вызовы
сохраняют прежнее поведение. Результат операции содержит имя и success/unchanged либо partial/failed с ошибками
подключений и необязательные данные проверенного registry download без временного URL.
Add и успешные/частичные update также содержат `changes.content`,
`changes.connections`, `changes.metadata`: замена копии, добавление/восстановление
подключений и изменение полей записи. Чистый повтор имеет все три `false`.
Telemetry использует эти признаки, чтобы отделить установочную работу от изменения только lock.
CLI возвращает код 0 для успеха, повтора без изменений и отмены; код 1
для ошибки или частичного результата. Ошибка источника, общей копии или lock
отклоняет Promise и даёт код 1.

## Выбор и пути

Повторяемый `-a` проверяет имя и убирает повторы до файловых изменений.
CLI add/find сначала выбирает область (без -g, в TTY), затем агентов.
Без `-a` открывается Clack: Claude Code, OpenCode и Codex отмечены,
Cursor и Pi доступны без отметки. Можно снять любой default; пустой выбор
не подтверждается. Стрелки/пробел/Enter управляют меню, Escape/Ctrl+C отменяют
до создания Installer, чтения источника или lock, HTTP и файловых изменений.
Оба потока должны быть TTY; для add без TTY нужны явные -a и --yes.
Затем add-ui показывает карточку и спрашивает подтверждение, по умолчанию «Нет».
-y/--yes пропускает только подтверждение. AddPreview берёт фактические
назначения из connection/resolveConnectionPath, включая сохранённые пути.
Registry reviewAdd выполняется после resolveArtifact, до скачивания и ветки
повтора; локальный — после подготовки снимка до записи копии/подключений/lock.
При отказе workspace очищается, новый пустой .agents удаляется только через rmdir.
UI signal отменяет metadata и подготовку до подтверждения; после него
установка завершается обычной транзакцией с повторной проверкой копии и путей.
`--force` не отключает меню, история выбора не сохраняется.

Общая копия — обычный каталог `.agents/skills/<name>` локально или
`~/.agents/skills/<name>` глобально. Lock — соответственно корневой
`skills-installer-lock.json` или `~/.agents/skills-installer-lock.json`.

| Агент       | Проект                  | Глобально                          |
| ----------- | ----------------------- | ---------------------------------- |
| Claude Code | `.claude/skills/<name>` | `~/.claude/skills/<name>`          |
| Codex       | `.agents/skills/<name>` | `~/.agents/skills/<name>`          |
| OpenCode    | `.agents/skills/<name>` | `~/.config/opencode/skills/<name>` |
| Pi          | `.pi/skills/<name>`     | `~/.pi/agent/skills/<name>`        |
| Cursor      | `.agents/skills/<name>` | `~/.cursor/skills/<name>`          |

Совпадающий путь читается напрямую, без ссылки на себя. Для остальных назначений
создаются ссылки; в проекте они относительные. Глобальные корни Claude/OpenCode
учитывают `CLAUDE_CONFIG_DIR`/`XDG_CONFIG_HOME` из context.env: пустая строка после
trim использует default, относительный override разрешается от cwd. Для существующих
подключений сохраняется путь из lock, даже после изменения env. Чтобы перенести
подключение, снимите его через remove и добавьте с новым env.
Назначения внутри общей папки skills и перенаправленные родители отвергаются,
чтобы не создавать циклические ссылки или менять содержимое чужого пути.

Проектные source/connection paths относительны; глобальные абсолютны. State schema
версии 1 допускает общий канонический путь Codex/OpenCode/Cursor локально и Codex
глобально; отдельные назначения уникальны. Локальная область в home и его symlink
запрещена, глобальная доступна. Области одного имени независимы.

## Добавление и владение

Одна транзакция StateStore держит блокировку области от чтения lock до конца
операции. Для известного источника установленный contentHash проверяется до
подготовки. Sources создаёт полный снимок во временном workspace. По имени
проверяется постоянная идентичность; смена имени источника требует remove/add.

Управление общей копией разрешено только при наличии собственного lock. Чужие
каталоги, файлы, ссылки и перенаправленные родители не перезаписываются даже с
force. Существующая отдельная ссылка принимается только при зарегистрированном
подключении и цели на общую копию. Отсутствующая ссылка воссоздаётся повторным add.
Vercel `skills-lock.json` и незарегистрированные скиллы не импортируются.

Хеш и владение повторно проверяются после подготовки и непосредственно перед
заменой, включая после вывода затрагиваемых агентов. Force разрешает заменить
правки управляемой копии; чужие назначения и смена источника остаются ошибкой.
Чистый повтор не заменяет каталог и не переписывает lock.

`prepareLocalSource` выбирает адаптер папки либо архива. Папка с именем,
оканчивающимся на `.tgz`/`.tar.gz`, остаётся папкой. Архив готовится независимо от
HTTP через `prepareArchive`; ограничения описаны в [Sources](sources.md).
В lock записываются `kind: archive`, постоянный путь и `archiveHash`; временный
путь распаковки не сохраняется. Архив и папка — разные источники даже при
одинаковом contentHash. Повторная упаковка того же содержимого обновляет archiveHash
в lock без замены общей папки и ссылок.

Registry использует [отдельный клиент](registry.md) и адаптер архивов из 006.
Для известного slug конфликт источника и защита ручных правок проверяются до HTTP.
Байты и метаданные проверяются до замены; source в lock содержит исходный registry
и slug, version — фактическую версию, policy — latest либо exact из исходного reference.
List/remove работают с registry-записью без сети. Add/update разрешают metadata
отдельно; одинаковые version/archiveHash и установленный contentHash позволяют
использовать существующую копию без скачивания. Чистый повтор не создаёт workspace;
смена только latest/exact записывает lock. Новые/отсутствующие ссылки используют
ту же копию в файловой транзакции. Изменение копии во время разрешения metadata
отклоняет повтор с предложением заново запустить операцию, включая force.

Новые успешные подключения объединяются с прежними; снятие отметки в новом меню
не удаляет подключение. При замене общая версия меняется для всех оставшихся
агентов, включая не выбранных в новом add. Частичный успех сохраняется с кодом 1.
Если все выбранные подключения отвергнуты, прежние содержимое и lock сохраняются.
Если подключения отказали после замены, файловая транзакция возвращает прежнюю
копию; новая неиспользуемая копия удаляется.

## Обновление

`update(name?, force = false, agents = [])` держит одну блокировку области на весь
пакет, сортирует записи по имени и читает актуальный lock перед каждым применением.
Имя ограничивает одну запись; агентский фильтр выбирает записи по пересечению,
затем ядро установки получает всех сохранённых агентов. Оно использует сохранённые
source/connection paths и registryUrl независимо от новых env/опций registry.
Отсутствующее явно указанное имя — ошибка; пустой набор возвращает успешный пакет.

Latest разрешается без версии, exact возвращает `pinned` с фактической версией
без HTTP и проверки копии, даже с force. Локальный источник готовится заново;
переименование скилла или смена типа источника не создаёт новую запись.
Общий метод `install` вызывается напрямую внутри транзакции; вложенных CLI и
повторного взятия блокировки нет. Переданные metadata используются адаптером
без повторного latest-запроса; refresh URL всё ещё привязан к разрешённой версии.

`reviewUpdate(UpdatePreview)` отделяет интерфейс от ядра. Preview содержит имя,
currentVersion/latestVersion, sourceKind, scope, всех агентов, available/unchanged/pinned
и причину изменения. Решения approve/decline/cancel передаются ядру: decline
возвращает skipped и продолжает пакет, cancel возвращает skipped с причиной
cancelled и останавливает оставшиеся записи. Без callback внутренний API применяет
обновления напрямую; CLI всегда передаёт callback с Clack-карточкой и confirm.
Registry preview показывается до скачивания, локальный — после подготовки снимка
и до применения. Отказ/отмена очищает подготовку; copy и lock сохраняются.
Только доступное изменение требует подтверждения; exact/unchanged показывают карточки.
CLI `--yes` явно подтверждает изменения без TTY, `--force` этого не делает.

`UpdateBatch` содержит `status: success/failed` и упорядоченные `results`:
обычные `LocalChange`, `pinned` или `skipped`. Ошибки источника/файлов/state записываются
в результат конкретной записи; следующие продолжаются. Partial/failed дают
общий failed. Повреждённый lock и занятая область отвергают пакет до установки.
Желаемые подключения сохраняются при частичном update; чужое назначение остаётся
ошибкой, успешные агенты используют новую общую версию. Если ни одно подключение
не удалось, прежние копия и запись сохраняются.

## Временная операция и откат

Постоянных tmp/backups нет. Installer создаёт уникальный
`.agents/.skills-installer-work-*` вне skills. Внутри находятся снимок источника,
`previous` с прежним содержимым и снятые ссылки до атомарной записи lock.
После успеха или успешного отката workspace удаляется.

Замена использует rename; обратные действия возвращают прежние файлы и снятые
ссылки, убирают созданные ссылки при ошибке до commit. Ошибка EXDEV также сохраняет
предыдущую установку; копирования поверх неё нет. Пустые родительские каталоги,
созданные для подключений, могут остаться после отказа.
`.skills-installer-operation.lock` и временный `.skills-installer-lock-*.tmp`
расположены рядом с lock и исключены из Git вместе с workspace.

Ошибка очистки после commit сообщает, что изменение уже сохранено: copy и lock
остаются согласованными. При ошибке очистки после успешного отката сообщается
путь workspace. При ошибке самого отката recovery-файлы сохраняются.

Crash journal вне MVP. После аварийного завершения могут остаться блокировка и
workspace; автоматической очистки нет. Блокировка исключает параллельных писателей
CLI, но не блокирует редакторы и подмены путей между системными вызовами.

## Список и удаление

List читает собственный lock без сканирования каталогов и обращения к источнику.
Фильтр агентов выбирает записи с любым из указанных агентов; вывод сохраняет всех
агентов записи. Показываются имя, версия, политика и агенты.
Пустое состояние не создаёт служебных каталогов.

CLI `list-ui.ts` показывает компактную таблицу Скилл/Версия/Политика/Агенты.
Область/фильтр и итог оформлены через
Clack intro/outro; пустой список и отсутствие совпадений фильтра имеют отдельные
сообщения. Общий `table.ts` переносит значения и выравнивает Unicode через
fast-string-width; данные не обрезаются. TTY не требуется, меню и подтверждений
нет; операция остаётся только чтением.

`updates-ui.ts` использует те же таблицы: строка Текущая/Доступная/Агенты до confirm,
затем общая таблица с колонкой «Результат» для всех обработанных записей. Unchanged/pinned
показываются только в общей таблице без отдельных карточек. `--yes` также оставляет
одну общую таблицу без повторного вывода каждой строки перед применением.

Remove без фильтра снимает всех зарегистрированных агентов, с `-a` — выбранных.
CLI `remove [names...]` без имён выбирает несколько записей собственного lock
через Clack multiselect без предвыбора, с обязательным выбором и максимум восемью
видимыми вариантами. Имена, версия/«локальная» и затрагиваемые агенты показаны в меню;
явные имена пропускают его. Повторы объединяются, неизвестные имена и отсутствие
подходящих подключений пропускаются с пояснением. Пустой список — код 0.
`remove-ui.ts` показывает таблицу Скилл/Версия/Агенты и одно подтверждение
по умолчанию «Нет». Отказ/Escape/Ctrl+C до удаления — код 0 без изменения файлов.
`--yes` пропускает confirm, но сохраняет меню без имён. Без TTY нужны явные имена,
а для существующих подключений — ещё и --yes. После согласия CLI последовательно
вызывает прежний remove(name, agents), передавая только показанные подключения,
чтобы сохранить агентов, добавленных во время диалога. Ошибки и исключения одного
скилла не прерывают остальные; итоговая таблица содержит колонку «Результат» и общие счётчики.
Partial/failed дают код 1. Схема lock и API Installer не меняются.

Ссылки проверяются и переносятся в workspace. Прямое подключение снимается только
из записи, общая копия остаётся до последнего зарегистрированного агента. Последнее
удаление убирает общую копию, включая ручные правки, без хеша и force.
Исходник сохраняется. Отсутствующие назначения допускаются; чужие объекты сохраняются
с ошибкой по агенту. Успешные удаления при других ошибках сохраняются с кодом 1.
Снятие прямого подключения не гарантирует исчезновение видимости скилла у агента.

Проектные содержимое, lock и относительные ссылки коммитятся вместе; список агентов
общий для проекта. Глобальные установки каждый разработчик управляет отдельно.

Тесты подменяют файловые операции, подготовку, StateStore, TTY-потоки и cwd/home/env.
HTTP запрещён по умолчанию, реальные установки агентов не используются. Clack
проверяется настоящими клавишами через управляемые потоки и результатом установки.

## События registry (010)

CLI передаёт необязательный `Telemetry` в Installer и ожидает `flush()` в finally
после add/update, включая исключение. Без этой опции внутренний Installer не отправляет
события. Контекст формируется после определения registry-источника; download использует
существующий callback после проверки байтов. Install отправляется один раз после
возврата результата или обрабатываемого исключения общего метода установки.
Статусы success/partial/failed сохраняются; UpdateSkipped и AddSkipped подавляют событие.

Успешное изменение только metadata, unchanged и pinned не отправляют install.
Событие включает запрошенных и уже зарегистрированных затрагиваемых агентов;
update с фильтром всё равно учитывает всех агентов общей копии. До разрешения
metadata версия latest неизвестна и отсутствует; exact указывает запрошенную версию.
Локальные источники, list/remove и отмена выбора агентов не отправляют события.
Доставка не влияет на транзакцию и результат; контракт — в [telemetry.md](telemetry.md).

## Find и версия подтверждённой registry-установки

CLI find-ui показывает асинхронный поиск с оформлением Clack. После паузы
ввода от двух символов find-search получает варианты от backend по slugPrefix, отменяет старые
запросы и игнорирует запоздалые ответы. Во время запроса/ошибки/пустого результата
установка недоступна. Более короткий префикс отменяет запрос и очищает результаты.
В строках только slug, версия и количество установок; список прокручивается. После выбора скилла идут область, агенты, карточка и подтверждение. До выбора
агентов нет запроса artifact; до финального подтверждения нет скачивания или установки.
Отмена загрузки/поиска/агентов освобождает ввод и raw mode.

Find передаёт RegistrySelection с slug/version и policy=latest в `addRegistry`,
который вызывает то же
ядро add с явной registry-идентичностью. Совпавшая локальная папка не влияет на
выбор источника. Версия задаёт артефакт текущей операции; latest в lock позволяет
последующему update получать новые версии. Без явной policy addRegistry сохраняет
правило reference: version означает exact. URL и флаги берутся из find. В том числе действуют scope, force, явные агенты и отключение статистики.
События имеют operation add; отдельное событие find не создаётся.
