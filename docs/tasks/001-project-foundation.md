# 001. Каркас проекта и инструменты

## Цель и входные условия

Получить запускаемый каркас CLI на [согласованном стеке](000-stack.md), с командами проверки и изолированной средой тестов. Задача 000 согласована. Реализация начата по поручению пользователя 2026-10-12: «Давай приступим к реализации первой задачи».

Общие требования: [SPEC.md](SPEC.md). Исходные примеры: `../../../skills/package.json`, сборочная конфигурация и тестовые вспомогательные функции форка. Переносить только нужные элементы, не копировать его package.json целиком.

## Работы

1. Если проект всё ещё вне Git — инициализировать локальный репозиторий; не создавать remote, push или коммит автоматически.
2. Настроить один npm-пакет с рабочим именем `skills-installer`, ESM и Node.js >=22.20. Зафиксировать совместимую версию npm и `package-lock.json`; для воспроизводимой установки использовать `npm ci`.
3. Выбрать совместимые стабильные версии согласованных инструментов, проверить engines/peerDependencies и записать выбранные версии в результат задачи.
4. Настроить TypeScript strict, tsdown, tsx, Vitest, oxlint, Prettier. Commander отвечает за разбор команд; node:util.parseArgs не использовать.
5. Добавить scripts из 000: dev, build, type-check, lint, format, format:check, test, test:run, changeset, package:check. Запускать через `npm run <script>`; аргументы CLI передавать после `--`. Проверочные scripts не исправляют файлы автоматически.
6. Подготовить исполняемую точку входа с shebang, bin-мapping и ESM-сборкой. Реализовать `--help` и `--version`; неизвестная команда возвращает 1. `install` не регистрировать.
7. Инициализировать Changesets без автоматической публикации, повышения версий и push. Подключить publint как инструмент проверки упаковки.
8. Определить границы CLI, Sources, Registry client, Installer, State, Telemetry и минимальные внутренние контракты подготовленного источника, корней, записи установки и результата операции. Не создавать фиктивные реализации будущих команд.
9. Подготовить временные корни, подменяемый home/cwd/env/HTTP и очистку тестовых данных. Не использовать реальные пользовательские каталоги агентов.
10. Добавить README с запуском разработки и проверок, правила упаковки и необходимые лицензионные уведомления. Учесть runtime-зависимости отдельно от devDependencies.

## Не входит

Установка скиллов, подключения агентов, registry-запросы, release/publish и перенос обработчиков форка целиком. Changesets не является механизмом аппрува задач.

## Критерии готовности

- [x] Исходники запускаются через tsx, сборка — через Node без tsx/TypeScript во время исполнения.
- [x] `--help` и `--version` работают в отдельном процессе; неизвестная команда и `install` не выполняют действий.
- [x] Есть отдельные проверки типов, линтинга, формата и тестов.
- [x] Выбранные зависимости совместимы с согласованной средой сборки; зафиксированы их версии.
- [x] Runtime-зависимости проверены в отдельном каталоге через `npm ci --omit=dev`; запуск npm-архива остаётся в 011.
- [x] Тестовый helper гарантирует подмену корней и очистку временных файлов.
- [x] Сохранены лицензии фактически перенесённого кода.

## Проверки

- Выполнить общие проверки из [индекса](README.md#общие-проверки-перед-ревью-реализации).
- Запустить dev и собранную точку входа с `--help`, `--version`, неизвестной командой; проверить коды завершения.
- Проверить bin-путь, shebang, содержимое dist и отсутствие ссылок на исходники, нужные лишь для разработки.
- Проверить запуск тестов в изолированном корне и отсутствие изменений в реальном home.
- Запустить первоначальную проверку publint. Финальная установка настоящего npm-архива и платформенная матрица относятся к 011.

## Результат для ревью

Подготовлен каркас `skills-installer` версии `0.1.0`. Доступны справка и версия; аргументы будущих команд отклоняются с кодом 1. Бизнес-операции последующих задач не реализованы.

### Изменения

- Создан локальный Git-репозиторий с веткой `main`; коммитов и remote нет.
- Добавлены `package.json`, `package-lock.json`, strict `tsconfig.json`, конфигурации tsdown/Vitest/oxlint/Prettier и `.gitignore`. npm `11.19.0` закреплён в `packageManager`; `engines.node` — `>=22.20.0`.
- `src/cli.ts` и `src/cli/program.ts` используют Commander. `dist/cli.mjs` — ESM с shebang, режимом `755` и встроенной версией из манифеста. Внешняя зависимость сборки — Commander; runtime-импортов исходников, tsx и TypeScript нет.
- `dev` использует официальный [загрузчик tsx](https://tsx.is/dev-api/): `node --import tsx src/cli.ts`. Первоначальный `tsx src/cli.ts` столкнулся с лимитом длины Unix-сокета в длинном TMPDIR macOS; после изменения все dev-сценарии повторены успешно.
- В `src/runtime.ts`, `src/sources/types.ts`, `src/installer/types.ts`, `src/state/types.ts` определены минимальные внутренние контракты. Границы шести модулей описаны в `docs/architecture.md`; схема lock и реализации остаются следующим задачам.
- `tests/helpers/test-environment.ts` создаёт временные cwd/home/env, не меняет глобальные process.env/cwd, запрещает HTTP по умолчанию и очищает файлы в `finally`. Пути конфигурации агентов нельзя вывести из fixture через env overrides. Написаны 13 тестов CLI/изоляции в двух файлах.
- Changesets инициализирован: `commit: false`, `access: restricted`, без GitHub-интеграции и автоматического релиза. Добавлены README, MIT LICENSE и дословное уведомление форка в `ThirdPartyNoticeText.txt` для адаптированного тестового helper.
- Prettier отформатировал существующие Markdown-файлы, включая AGENTS.md и документы задач, без изменения требований и статусов будущих задач. Существующие `.agents/skills/vitest` и `skills-lock.json` не изменены.

### Ограничения

- Финальная установка настоящего npm-архива и Linux-матрица **не выполнялись**, относятся к 011. Здесь проверены состав dry-run и отдельная копия сборки с production dependencies; проверка архива этим не подменяется.
- Backend и обнаружение скиллов агентами **не проверялись**: функциональности ещё нет, в объём 001 они не входят.
- Git создан с пустой историей: обычный `git diff` ещё не показывает untracked-файлы. Для ревью просмотрены новые исходники/конфиги/тесты и область изменений, выполнена проверка whitespace новых файлов. Коммитов, push, публикации и изменений соседних проектов нет.
- Замечаний пользователя к реализованному результату нет. Пользовательский аппрув получен 2026-10-12; статус `approved`.
