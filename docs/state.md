# Состояние установок

State — внутренний API задачи 002. Все корни передаются явно; Git-root не ищется.
Миграция старого состояния и команды установки в эту задачу не входят.

## Области и формат

`getStatePaths({ cwd, home }, scope)` принимает абсолютные корни и `project`/`global`.
Проект использует точный cwd, глобальная область — home.

Проектная область в home запрещена с ошибкой `PROJECT_IN_HOME`. Нормализованное
совпадение путей обнаруживается при вычислении корней; symlink-алиас home — перед
чтением или созданием состояния по dev/inode каталогов. Глобальная область доступна
даже при cwd=home. Проверка не создаёт служебные файлы и не изменяет глобальный lock.

Структура обеих областей одинакова:

```text
.skills-installer/
  lock.json
  skills/<name>/
  tmp/
  backups/
  operation.lock
```

`getSkillDirectory` проверяет безопасность имени: запрещены пустое имя, `.`/`..`,
разделители, управляющие символы и имена длиннее 255 байт UTF-8. Чтение frontmatter
остаётся в 003.

Пример проектного lock версии 1:

```json
{
  "version": 1,
  "skills": {
    "demo": {
      "name": "demo",
      "source": { "kind": "directory", "path": "sources/demo" },
      "version": null,
      "policy": "local",
      "contentHash": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
      "agents": ["codex"],
      "connections": [{ "agent": "codex", "path": ".agents/skills/demo" }]
    }
  }
}
```

| source.kind | Постоянная идентичность | policy           |
| ----------- | ----------------------- | ---------------- |
| directory   | path                    | local            |
| archive     | path                    | local            |
| registry    | registryUrl, slug       | latest или exact |

Registry требует фактическую версию. Локальный источник допускает `null`, если версии
нет. Archive и registry требуют `archiveHash`, directory его не имеет. Хеши — 64
hex-символа SHA-256, нормализуемые к нижнему регистру.

`agents` — непустой список желаемых агентов. Управляемые `connections` могут быть
подмножеством этого списка при частичном восстановлении. Повторы, неизвестные поля,
агенты, некорректные имена, хеши и политики отклоняются. Ключ записи совпадает с `name`.
Один путь подключения не может принадлежать разным записям.

Проектные локальные источники относительны cwd, глобальные — абсолютны. Исходник вне
проекта может храниться как `../source`. Для новой глобальной записи относительный
исходник разрешается от cwd вызова. Проектные подключения относительны cwd и не могут
выходить наружу; глобальные — абсолютны. Запись принимает абсолютные runtime-пути,
но чтение отклоняет уже сохранённые абсолютные пути проектного lock.

`resolveSourcePath`/`resolveConnectionPath` разрешают пути после переноса проекта.
Идентичность источника нормализуется лексически без разыменования ссылок. Registry
сохраняет HTTP(S) base URL без credentials, query и fragment, а не URL артефакта.
Версия и digest не входят в идентичность. Другой источник существующего имени даёт
`SOURCE_CONFLICT`; нужна отдельная запись удаления перед добавлением.

## Чтение и запись

```ts
const paths = getStatePaths(runtime.roots, 'project');
const store = new StateStore(paths);
const lock = await store.read(); // null только при отсутствии

await store.update((previous) => {
  const current = previous ?? createEmptyLock(); // команда решает, допустимо ли отсутствие
  return { version: 1, skills: { ...current.skills, demo: record } };
});
```

`read` не создаёт каталогов. Повреждённый JSON/неполная запись дают `INVALID_LOCK`,
неизвестная целая версия — `UNSUPPORTED_LOCK_VERSION`. Ошибки filesystem сохраняются,
не превращаются в пустой lock. State-root и lock не могут быть symlink; lock должен
быть обычным файлом.

`write` сохраняет снимок под блокировкой. Для изменения отдельных записей используется
`update`, удерживающий её на всём read-modify-write. `transaction` позволяет удержать
ту же блокировку для файловой операции Installer с прямыми `state.read`/`state.write`.
Все асинхронные операции нужно await-ить внутри callback. Произвольные изменения callback
не откатываются самим State; rollback установки относится к Installer в 004.

`operation.lock` создаётся эксклюзивно через `wx`. Конкурентный писатель получает
`SCOPE_BUSY` до чтения и изменений; другие области доступны независимо. При обработанной
ошибке блокировка освобождается, завершённый transaction повторно использовать нельзя.
После аварии lock может остаться: автоматического снятия, ожидания/retry и crash journal
в MVP нет. Ручное снятие требует убедиться, что операция уже не выполняется.

Новый lock валидируется и сериализуется с отсортированными именами, агентами и
подключениями. Временный файл эксклюзивно создаётся в `tmp`, записывается, fsync-ится,
закрывается и переименовывается на той же файловой системе. Ошибки записи/rename
сохраняют прежний lock; частичная запись не видна читателям. Временный файл очищается
после успеха/ошибки. `StateFileIO` подменяет writeTemporaryFile/rename в тестах.

`.gitignore` сохраняет lock, ресурсы skills и проектные подключения даже при совпадении
с общими правилами `*.tgz`, `node_modules`, `dist`, `.DS_Store`. Служебные tmp/backups/lock
игнорируются и во вложенных проектах; одноимённые ресурсы внутри skills сохраняются.

## Content hash

`hashDirectory(absolutePath)` вычисляет SHA-256 без исключения скрытых файлов, `.git`,
`node_modules` и ресурсов, созданных скриптом. Каждое поле имеет длину `uint64BE` и байты.
Первое поле — `skills-installer-content-v1`, корневой относительный путь пустой.
Запись содержит путь и тип; файл — executable-флаг и bytes, symlink — текст target.
Папки, включая пустые, обходятся preorder; имена сортируются по байтам Buffer.compare.

Executable равен 1 при любом бите `0o111`. Прочие permissions, абсолютный корень,
mtime и владельцы не учитываются. Файлы читаются блоками 64 KiB. Смена inode/типа
между lstat/open и изменение размера при чтении дают ошибку. Относительный корень
отклоняется, чтобы не использовать настоящий cwd процесса.

Любая symlink, включая корневую, сломанную и циклическую, хешируется как ссылка без
чтения target. Обычный файл открывается с `O_NOFOLLOW | O_NONBLOCK`; специальные записи,
например FIFO, отклоняются до чтения. В 003 источники разыменуют ссылки до хеширования.

Hash не является атомарным snapshot при произвольных конкурентных изменениях дерева.
Блокировка защищает CLI-операции между собой, но не блокирует редакторы/сторонние
процессы. Полной openat-защиты от подмены промежуточных каталогов здесь нет.

## Проверки

```sh
npm run test:run -- tests/state.test.ts tests/state-git.test.ts tests/content-hash.test.ts
```

Тесты используют временные home/cwd, подмену ошибок записи/rename, отдельные процессы,
перенос проекта, бинарные данные и symlink. Git-проверка создаёт свой временный
репозиторий и не изменяет `.git` проекта.
