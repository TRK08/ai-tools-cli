# Архитектура

Один внутренний TypeScript/ESM-пакет. Commander разбирает аргументы, терминальные
компоненты оформляют меню, сценарии вызывают Installer напрямую.
[Пользовательские команды](../README.md#команды)

| Модуль                                                  | Ответственность                                             |
| ------------------------------------------------------- | ----------------------------------------------------------- |
| [CLI](../src/cli/program.ts)                            | Аргументы, потоки, регистрация обработчиков                 |
| [Сценарии](../src/cli/commands/)                        | Область, меню, выбор и обработка результата                 |
| [UI](../src/cli/ui/) и [терминал](../src/cli/terminal/) | Готовые модели, отображение, ввод и очистка TTY             |
| [Агенты](../src/agents/) и [пути](../src/paths/)        | Каталог подключений, переносимые имена и нативные операции  |
| [Installer](../src/installer/)                          | План, проверки владения, пакетная транзакция                |
| [Registry](../src/registry/)                            | Релизы, поиск, проверенный ZIP                              |
| [Sources](../src/sources/)                              | Проверка состава ZIP и подготовка файлов                    |
| [Config](../src/config/)                                | Сохранённый registry и пользовательский корень              |
| [Store](../src/store/)                                  | Межпроцессная подготовка и проверка распакованных снимков   |
| [State](../src/state/)                                  | Lock version: 1, блокировка, атомарная запись и хеширование |
| [Telemetry](../src/telemetry/)                          | Ограниченная по времени доставка событий пакета             |

`RuntimeContext` передаёт cwd, home, env и HTTP. `CliContext` добавляет версию CLI
и независимые stdin/stdout/stderr. Реальные зависимости создаёт [точка запуска](../src/cli.ts).
[executeCli](../src/cli/run.ts) направляет сообщения в заданные потоки и возвращает 0/1.

## Направления зависимостей

`program` вызывает сценарии. Сценарии связывают Installer и Registry с UI.
Представления принимают готовые данные. Общий терминал зависит от Node и библиотек
оформления. Registry не использует UI или состояние. Sources получает байты,
проверенные HTTP-клиентом, и готовит снимок по контракту реестра.

Внутри папки используются относительные импорты, между модулями — алиас `@/`
и именованные экспорты из их `index.ts`. Компонентные тесты могут импортировать
реализацию напрямую. Импорты не выполняют I/O. При запуске tsx из другого cwd
тестовые helpers передают явный `TSX_TSCONFIG_PATH`.

## Основной поток

1. `add` проверяет аргументы, получает текущий или точный релиз и проверяет явный
   состав до выбора области, скиллов и агентов. `find` передаёт тому же сценарию
   точный пакет, версию и один компонент. Полученные метаданные используются
   до конца установки без повторного запроса релиза.
2. Installer открывает StateTransaction, проверяет сохранённое владение и строит
   план. CLI показывает состав, версии, подключения и ручные правки.
3. После подтверждения Store проверяет запись по registry/digest под блокировкой ключа.
   При промахе Registry скачивает ZIP точной версии, Sources проверяет состав,
   Store атомарно публикует снимок. `preparePackage` создаёт обычные независимые
   staging-копии в области установки и сверяет их содержимое.
4. `applyPackage` сверяет текущее состояние с планом, применяет файлы с обратными
   операциями и отдаёт управление для атомарного сохранения lock. FileTransaction
   владеет откатом и очисткой workspace.
5. Статистика отправляется за фактическую загрузку и за успешный commit.
   CLI ждёт `Telemetry.flush()` перед выходом.

Update сначала выбирает область и читает её lock, чтобы определить пакеты и их
исходные registry, затем разрешает текущий релиз каждого подходящего пакета.
Сводка и выбор обновлений работают с уже разрешёнными версиями. Каждый пакет
применяется отдельно. Remove читает установленный состав и использует ту же
файловую транзакцию для снятия связей. List читает только lock.

## Терминал и отмена

`runPrompt` владеет listeners, raw mode, экраном и курсором до завершения диалога.
Select, confirm и multiselect освобождают ресурсы при отказе, Esc/Ctrl+C, EOF и
ошибке потока. `RegistryFindSearch` использует debounce, отменяет прежние запросы
и игнорирует ответы устаревшей ревизии. Поиск от трёх символов, debounce 200 мс. Подготовка add до подтверждения использует
`runAddPreparation`, передаёт AbortSignal в HTTP и хеширование и освобождает ввод
перед открытием следующего диалога. `executeCli` устанавливает и снимает обработчики
SIGINT/SIGTERM; общий сигнал доступен диалогам и всем стадиям Installer. До записи
lock отмена откатывает пакет, после неё сохраняет результат и останавливает следующие
пакеты. Откат/очистка/освобождение блокировок выполняются без отменённого сигнала.

## Расширение

Команды добавляются в `cli/commands/` и явно регистрируются в `createProgram`.
UI получает модели без доступа к HTTP и lock. Новые меню используют общий
`PromptStreams` и `terminal`. Новое подключение описывается записью каталога
агентов с видами direct или link для обеих областей.
`project.directory(roots)` задаёт также допустимый проектный путь в lock;
валидатор не содержит имён отдельных агентов. Direct означает общий каталог,
link — отдельное назначение внутри проекта. Глобальный env-путь вычисляется
при новом подключении, а сохранённое назначение читается из lock без пересчёта.
Расширение каталога проверяется полным add/list/update/remove и откатом на
временных корнях с тестовым агентом `.example/skills`.

Изменяющая операция проверяет владение и готовит файлы до мутации. Повторная
проверка после подтверждения защищает от замены уже показанного объекта.
Запись lock происходит после успешного применения под той же блокировкой.
Тесты подменяют HTTP и корни и проверяют rollback на настоящих временных файлах.

Экспортируемые функции, публичные методы и внутренние операции с отдельным
контрактом документируются на русском в TSDoc. [Правила проекта](../AGENTS.md)
