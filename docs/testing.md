# Проверки

| Набор              | Команда                                                                        | Проверяет                                                               |
| ------------------ | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| Unit и integration | `npm run test:run`                                                             | Реестр, ZIP, lock, агенты, терминал, файловые транзакции и сценарии     |
| Built CLI          | `npm run test:e2e`                                                             | Свежая сборка, процессы CLI, локальный HTTP, ZIP и project/global       |
| Git                | `npm run test:git`                                                             | Commit/clone временных копий, portable paths, байты и локальные команды |
| Пакет              | `npm run package:check`, `npm run package:smoke -- /absolute/path/package.tgz` | Состав и реальная установка npm bin                                     |

Тесты используют отдельные project/home/env. HTTP-транспорт в unit и integration
подменяется. E2E обращается к локальной модели Core. Она регистрирует запросы,
проверяет тело событий и позволяет испортить ZIP или вернуть ошибку HTTP.

Штатный `npm run test:e2e` сначала выполняет build; ошибка сборки останавливает
запуск Vitest. Аргументы после `--` фильтруют тесты, например
`npm run test:e2e -- tests/e2e/lifecycle.test.ts`. При прямом запуске Vitest
helper проверяет только наличие bin и не гарантирует его свежесть.

ZIP fixtures согласуют descriptor, размеры и хеши до внесения конкретного
дефекта. Проверки отдельно покрывают пути и коллизии, заголовки, типы объектов,
состав и границы 1000 записей, 25 MiB данных с descriptor, 1 MiB descriptor,
12 уровней и 512 байт пути. Отказ проверяется до записи файлов. Контрольные
отключения защит выполняются только в изолированной копии проекта.

Пакетные тесты проверяют смену единой версии, исчезнувшие компоненты, ручные
правки, отказ, отмену, чужие каталоги, ошибки отдельного пакета, rollback
общих копий и ссылок Claude и сохранность lock. Интерактивные сценарии
используют управляемые терминальные потоки.

Для сквозной проверки с текущим Core используйте опубликованный тестовый релиз
в отдельном project/home. Можно прогнать поиск, add точной версии, update,
list и remove с `--without-stat`. Такая проверка покрывает реальные JSON-ответы,
подписанные ссылки и ZIP из Core. Для проверки статистики на общем Core нужна
отдельная тестовая установка с разрешением на запись счётчиков.

Доработки registry/store покрыты сохранением config между процессами, приоритетами
URL, повреждением снимка и executable bits, независимостью установок и единственной
загрузкой при параллельных процессах. Проверяются восстановление при прежней версии,
отмена до/после commit, SIGINT/SIGTERM при загрузке и применении в собранном CLI,
освобождение блокировок, 35 пакетов в remove при 80×24, поиск/лимиты/серверный рейтинг.
Git roundtrip проверяет relative symlink Claude, режим 120000 и чтение из другого
checkout без переустановки. На Windows системные сигналы проверяются отдельно:
POSIX SIGINT/SIGTERM e2e помечены skip; нативный Ctrl+C требует ручной приёмки.
Config дополнительно проверяется на восстановление повреждённого содержимого,
сбои записи и отмену, подмену файла и чужие объекты без HTTP. Дополнительный
агент существует только в изолированном тестовом каталоге: проходит полный
lifecycle, сериализацию lock, проверки назначения и откат commit.
