# 007. Установка из registry

## Цель и входные условия

После аппрува 006 установить опубликованный скилл по slug или точной версии. Использовать [SPEC.md](SPEC.md), `../../../skills/src/registry-source.ts` и реальный контракт `../../../ai-tools-core/docs/openapi/swagger.yaml`.

Backend и его контракт в этой задаче не изменяются. Registry-клиент — внутренний модуль без UI, пригодный для будущего выделения в библиотеку.

## Работы

1. Разобрать `slug` и `slug@version`, сохранив проверки slug и полного SemVer из подходящего кода форка. Локальные пути/архивы не должны ошибочно распознаваться как registry.
2. Вычислять URL в порядке `--registry` → `SKILLS_API_URL` → `http://localhost:8000`. Проверять HTTP(S)-адрес; не вводить авторизацию или SKILLS_API_TOKEN.
3. Получать метаданные через `GET /api/v1/skills/{slug}/artifact` и `?version=...`. Проверять соответствие ответа запросу: slug, версию, SHA-256, размер, формат и URL.
4. Разделить получение метаданных и скачивание: будущий update сможет сравнить версию/хеш до скачивания, restore — запросить точную записанную версию.
5. Скачивать с тайм-аутом и лимитом, проверить фактические размер и SHA-256 до распаковки. Передать архив в общую подготовку из 006.
6. При истечении URL получить новую ссылку для изначально разрешённой версии. Digest/размер не должны меняться; повторную попытку ограничить, не переходить на новый latest.
7. Проверить `name` из SKILL.md против запрошенного slug. Сохранить исходный registry, slug, фактическую версию, хеш архива и contentHash, но не подписанный URL.
8. Add без версии сохраняет latest, с версией — exact. Не переносить старые lock-форматы и ветви Git-источников.
9. Показать понятные ошибки отсутствующего скилла/версии, недоступности registry, некорректного ответа и повреждения артефакта, используя реальные ответы backend.
10. Обновить README и Changeset. Подготовить данные о фактическом скачивании для подключения событий в 010, пока события не отправлять.

## Критерии готовности

- [ ] `add demo` и `add demo@1.2.3` работают с меню либо явным `-a`, в обеих областях.
- [ ] В lock хранится постоянная идентичность, а не временный URL.
- [ ] Истёкшая ссылка обновляется без смены выбранного артефакта.
- [ ] Несовпадение размера, SHA-256, версии или имени отвергается до изменения установки.
- [ ] Пользовательский registry сохраняется как источник будущих update/restore.
- [ ] Отмена меню не обращается к registry; неудачная сеть не удаляет старую установку.

## Проверки

- Общие проверки из индекса; HTTP-тестовый сервер с ответами по реальному контракту.
- Latest, exact, приоритет URL, локальный источник против registry reference.
- 404 скилла/версии, 503, тайм-аут, неверный JSON/метаданные, неверный формат.
- URL истёк до скачивания, 401/403 скачивания, успешное обновление URL, изменённая идентичность при refresh, повторно истёкший URL.
- Несовпадение фактических размера/хеша и имени в SKILL.md; сохранность предыдущей установки.
- Несколько агентов и обе области; секретные/временные query-параметры URL не попадают в lock.
