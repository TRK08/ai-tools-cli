# Установка и подключения

[Installer](../src/installer/installer.ts) предоставляет единый фасад жизненного цикла всех трёх источников.
Внутренние методы: `add`, `addRegistry`, `update`, `list`, `remove`. CLI передаёт
область, агентов, подтверждения и Telemetry; прямой `add` по умолчанию выбирает Codex.

## Разделение обязанностей

Фасад создаёт зависимости, держит блокировку области и обрабатывает пакет update.
`install` координирует одну операцию, `source` выбирает и готовит источник,
`inspection` проверяет копию и подключения, `plan` рассчитывает preview и InstallPlan
без I/O. `apply` применяет план и удаление через FileTransaction, `events` определяет
условия registry-событий. Контракты находятся в `installer/types.ts`.

InstallPlan фиксирует источник, версию, политику, проверенное прежнее состояние
и подготовленное либо заимствованное содержимое. Unchanged/metadata-only/apply —
намерение; фактические статусы и признаки изменений определяет исполнитель.
Повторные проверки перед мутациями сохраняются.

План разделяет три намерения: `unchanged`, `metadata-only`, `apply`.
Целый registry-повтор обходится без workspace и скачивания; смена только политики
пишет только lock. Локальный источник всё равно готовится, чтобы сравнить новый снимок.
`InstallationContent.ownership` отличает подготовленный снимок от заимствованной копии.
Фактические `changes.content/connections/metadata` формируются после применения,
поэтому частичный отказ не выдаётся за полностью выполненный план.

Callbacks интерфейса возвращают решение координатору и не изменяют установку сами.
Файловый исполнитель получает уже выбранное содержимое и состояние, затем повторно
проверяет копию и назначения. При изменении копии/подключений после preview `unchanged`
операция не должна незаметно заменить подтверждённый результат.
Порядок и места расширения — в [архитектуре](architecture.md#добавление-источника).

## Пути агентов

`<name>` добавляется к каждому каталогу из таблицы. Правила путей, тип подключения,
названия и закреплённая группа задаются в едином [каталоге](../src/agents/catalog.ts).
Таблица описывает новые подключения.

| Агент         | Проект            | Глобально           |
| ------------- | ----------------- | ------------------- |
| `claude-code` | `.claude/skills/` | `~/.claude/skills/` |
| `codex`       | `.agents/skills/` | `~/.agents/skills/` |
| `opencode`    | `.agents/skills/` | `~/.agents/skills/` |
| `pi`          | `.agents/skills/` | `~/.agents/skills/` |
| `cursor`      | `.agents/skills/` | `~/.agents/skills/` |

Глобальный Claude учитывает `CLAUDE_CONFIG_DIR`.
Относительный `CLAUDE_CONFIG_DIR` разрешается от cwd. Сохранённое подключение
Claude Code использует путь из lock, даже после смены env. Прежние пути
Pi/OpenCode/Cursor не поддерживаются и автоматически не мигрируются.
Перенаправленные через symlink родительские каталоги отклоняются.

Lock сохраняет agent/path/kind; вид подключения выводится из единого каталога
и проверяется схемой. Codex/OpenCode/Cursor/Pi используют общий каталог напрямую
(kind direct). Проектный Claude получает обычный самостоятельный каталог (kind copy)
на всех ОС. Обе копии и lock коммитятся вместе; общая копия остаётся даже при выборе
только Claude. Глобальный Claude использует symlink POSIX или junction Windows
с абсолютной целью (kind link), без fallback на копию. Старые проектные ссылки
не мигрируются; принимается только текущая схема чистых установок. Снятие прямого подключения из lock не скрывает
каталог от агента, пока остаются другие подключения.

Обе проектные копии и lock переносятся через Git без post-clone настройки;
нужны [attributes и ignore-правила](state.md#перенос-проекта-через-git), сохраняющие все bytes.
Глобальный Claude на Windows — junction с абсолютной целью, в том числе при
`CLAUDE_CONFIG_DIR`; fallback на копию и миграция старых установок не выполняются.
Существование каталога ещё не доказывает обнаружение агентом. Сценарии нативной проверки
перечислены в [проверках Windows](windows-validation.md).

## Add и update

StateStore блокирует область на всю операцию, включая подготовку и подтверждения;
пакетный update держит блокировку на весь пакет. Владение, родители и хеш всех
зарегистрированных копий проверяются до preview и перед применением, включая
повтор, metadata-only и выбор одного агента. Один record.contentHash — эталон всех
копий; ручная правка любой из них требует --force. Изменение после preview
отменяет план, в том числе при force. `--force` разрешает заменить правки управляемой копии,
но не чужие назначения и не источник уже установленного имени.

Новые подключения объединяются со старыми. Ошибка изменения уже зарегистрированного
назначения или записи lock откатывает весь скилл: общая копия и Claude не могут
остаться на разных версиях. Ошибка нового подключения допускает partial, если
прежние назначения согласованы. Если все запрошенные подключения отказали,
прежние копии и lock сохраняются.

Registry-повтор с совпадающими версией, archiveHash и contentHash обходится без
скачивания. Новую Claude-копию в этом случае можно получить из проверенной общей
копии. Чистый повтор не переписывает каталоги, файлы и lock; смена только latest/exact
меняет лишь lock. Эти пути не создают workspace без файловых изменений.
Локальный источник готовится заново. Exact пропускается update без HTTP и проверки копии,
включая запуск с force. Агентский фильтр update выбирает записи, затем обновляет всех их агентов.

`reviewAdd(AddPreview)` и `reviewUpdate(UpdatePreview)` возвращают approve/decline/cancel.
Registry-версия фиксируется до подтверждения; локальный снимок используется однократно.
Отказ update пропускает запись, отмена останавливает пакет, ошибки отдельных записей
не мешают остальным. Уже применённые результаты сохраняются.

## Remove и list

List читает только собственный lock: без сканирования, сети или создания каталогов.
Фильтр агентов оставляет подходящие записи; таблица показывает всех агентов записи.

Remove снимает выбранную копию/ссылку Claude; при других агентах общая копия остаётся.
После последнего подключения удаляет и общую копию вместе
с ручными правками, без проверки хеша. Исходник остаётся. Чужие объекты не удаляются;
успешные удаления при ошибках других подключений сохраняются как partial.

CLI подтверждает общий список и передаёт в remove только показанных агентов, сохраняя
добавленных за время диалога. Remove использует текущую запись по имени, включая
заменённые за время диалога источник/версию.

## Транзакция и ограничения

`FileTransaction` хранит снимок, staging и резервные копии каталогов в
`.agents/.skills-installer-work-*`. Перед перемещением подготовленного снимка в общую
папку из него создаётся staging для Claude и проверяется его хеш; повторной подготовки
источника нет. Rename и создание ссылок имеют обратные операции. Глобальную ссылку
снимают без rename: журнал сохраняет исходный target и тип ссылки для восстановления.
Поэтому CLAUDE_CONFIG_DIR может находиться на другом локальном томе; снимается только
объект ссылки, включая dangling link с ожидаемой целью.
Сначала применяются файлы, затем записывается lock; после успеха или успешного отката
workspace удаляется с maxRetries: 3, retryDelay: 100. Эти повторы применяются только
к собственным временным ресурсам. Все временные ресурсы адаптера находятся внутри этой базы;
Installer не вызывает отдельный cleanup снимка. Заимствованная установленная копия
не является временным ресурсом. EXDEV завершает операцию с сохранением прежней установки.

Ошибка очистки после commit не откатывает записанное состояние. При неудачном откате
или очистке сообщение указывает оставшийся workspace. Пустые созданные родители могут остаться.
Crash journal отсутствует: после аварии возможны workspace и файл блокировки.
Перед ручным восстановлением нужно убедиться, что процесс завершён, и сверить lock с копией/backup.

Блокировка защищает от других писателей CLI, но не от сторонних редакторов.
До подтверждения add AbortSignal останавливает подготовку локальной папки/архива
и проверку хешей установленных копий до preview, в том числе с force.
Результат cancelled возвращается после закрытия ресурсов, очистки workspace и
освобождения блокировки; ошибки очистки не скрываются. После подтверждения
операция завершается транзакционно; отмена подготовки update не расширяется.
Контракты источников и состояния — в [Sources](sources.md) и [State](state.md).
