# Границы модулей

CLI содержит запуск, справку и версию из задачи 001. В 002 реализован модуль State:
пути, схема lock, валидация, запись, блокировка и content hash. В 003 добавлена
подготовка локальной папки в Sources: YAML, снимок с разыменованными ссылками и
очистка. В 004 Installer координирует локальный `add`/`list`/`remove` для Codex,
включая проверки принадлежности, защиту правок и откат файлов до сохранения lock.
После ревизии 004 общая копия находится в `.agents/skills`, Codex читает её напрямую,
lock — в корне проекта. Один временный workspace заменяет постоянные tmp/backups.
В 005 Installer подключает пять агентов в двух областях, а CLI выбирает агентов
через Clack до запуска операции. Пути и env вычисляются из RuntimeContext,
подключения добавляются и удаляются вместе с общей копией в файловой транзакции.
В 006 подключены локальные архивы, в 007 registry-клиент разделяет metadata и
проверенное скачивание; registry-адаптер использует общую подготовку архивов.
В 008 add/update вызывают один метод установки под блокировкой State; metadata
сравниваются до скачивания, пакетные ошибки изолированы по записям.
CLI оформляет обновления в `updates-ui.ts` через Clack; callback reviewUpdate
передаёт подтверждение/отказ/отмену в Installer до применения выбранного артефакта.
В 010 Registry получает поиск slugPrefix/карточку; backend фильтрует буквальный
префикс с учётом регистра. Find-search управляет debounce/abort/актуальностью ответа,
find-ui показывает асинхронный выбор с оформлением Clack, затем передаёт точный
registry reference в общий обработчик add: область, агенты, карточка и confirm; без TTY выводит таблицу.
Add-ui получает reviewAdd с фактической версией и назначениями Installer;
Registry-карточка запрашивается для этой версии до скачивания, локальный снимок
используется однократно после согласия. Installer передаёт исход registry-операции в Telemetry, CLI ожидает ограниченную доставку.
Внутренние API описаны в [state.md](state.md), [sources.md](sources.md),
[registry.md](registry.md), [installer.md](installer.md) и [telemetry.md](telemetry.md); публичный SDK не создаётся.

| Модуль                            | Ответственность                                                       | Граница                                                                       |
| --------------------------------- | --------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| CLI (`src/cli.ts`, `src/cli/`)    | Commander, Clack, аргументы, справка, вывод и код завершения          | Вызывает бизнес-операции напрямую; не запускает вложенный CLI                 |
| Sources (`src/sources/`)          | Подготовленная копия, постоянная идентичность, версия, хеши и очистка | Не знает об агентах, UI или записи lock; не изменяет источник                 |
| Registry client (`src/registry/`) | Контракт backend, metadata и загрузка через подменяемый HTTP          | Не зависит от UI; подписанный URL не попадает в постоянную идентичность       |
| Installer (`src/installer/`)      | Координация установки, подключения и результат операции               | Использует Sources и State; не разбирает CLI-аргументы                        |
| State (`src/state/`)              | Пути, схема lock, атомарная запись, блокировка и хеширование          | Работает с явно переданными корнями; внутренний API описан в state.md         |
| Telemetry (`src/telemetry/`)      | Best-effort события registry                                          | Использует подменяемые env/HTTP; ошибки доставки не меняют результат операции |

`src/runtime.ts` определяет `RuntimeContext`: `roots.cwd`, `roots.home`, отдельный
`env` и `http`. Операции получают его явно. Чтение реальных `process.cwd()`,
home, `process.env` и глобального fetch должно оставаться на границе приложения;
сервисы и тесты не меняют эти глобальные значения.

Минимальные внутренние модели:

- `PreparedSource`: подготовленная папка, имя/описание, идентичность, версия при
  наличии, `contentHash`, необязательные `archiveHash`/данные проверенного download, асинхронный `cleanup`.
- `SourceIdentity`: локальная папка, локальный архив или исходный registry URL и slug.
  Переносимые пути и нормализация реализованы в State.
- `InstallationRecord`: имя, источник, версия/политика, хеши, агенты и управляемые
  подключения. Lock версии 1 валидирует согласованность полей и переносимость путей.
- `OperationResult`: success/unchanged/cancelled с кодом 0 либо partial/failed с
  кодом 1 и сообщениями об ошибках. Add/update отдельно отмечают изменение копии,
  подключений и metadata; UpdateBatch включает также pinned для exact и skipped
  для отклонённых/отменённых обновлений.
  Telemetry использует отдельный v1-envelope backend.

Тестовый helper создаёт home, cwd и окружение внутри одного временного каталога,
подменяет HTTP и очищает данные после успеха и исключения. Дочерний процесс
запускается с временным cwd и env; переменные реальных registry, конфигурации агентов
и telemetry из окружения разработчика не наследуются.

Clack autocomplete установленной версии принимает синхронные варианты. Для
ответов сети find-ui использует собственный raw-keypress renderer с публичными
символами/intro Clack, общим переносом Unicode из table.ts и переданными потоками.
Запросы вынесены в find-search.ts; пользовательские установки/agent picker
сохраняют прежний Clack. Прямого чтения env и новых зависимостей нет.
